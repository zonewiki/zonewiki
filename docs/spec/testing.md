# Tests

Part of Leaf's spec (see `AGENTS.md` for the index).

How the suite is set up and what each module covers. The rules (run it, add tests with every change) are in `AGENTS.md`.

## Shared setup

`tests/conftest.py` holds the shared setup: it imports Leaf against a throwaway `LEAF_DATA`, and gives every test a fresh temp wiki (`wiki_dir`: the server and the deck pointed at it, every page/task cache emptied, just `index.md`; `git_wiki_dir`: the same as a git repo; `client`), plus helpers (`HOST`, `write_page`, `create_task`, `section_fields`) that modules import from `tests.conftest`. The browser tests' `wiki` fixture builds on `git_wiki_dir`.

**The Go port under the same tests** (`prototype/PORT.md`): with `LEAF_TEST_GO=1` (`./run.sh go [pytest args]`) the `client` fixture is `tests/goserver.py`'s `GoClient`, which takes the test client's calls and sends them over HTTP to a Go server (`go/`, built once per worker) started on the test's wiki; the browser tests' `wiki` fixture starts one on a port fixed for the session. The settings a test patches in `config` (`LEAF_PASSWORD`, `LEAF_HOSTS`, `LEAF_LOCALE` …) reach the server as its environment: when they change, it restarts on the same wiki (and port) before the next request; the browser's requests pass `_new_page`'s route, which checks. Leaf's docs folder, which `TestLeafHelp` points elsewhere (`manual.docs_root`), reaches it the same way, as its `-docs` flag. So does the semantic index a test puts in `retrieval.SEMANTIC` (with `test_semantic.py`'s `FakeEmbedder`), as `-semantic-test`: the server gets the same concept embedder and floors (`go/embedtest.go`), syncs once at start when Python's index has, and restarts after each sync that changed Python's index, so it sees the wiki as Python's index did. Only tests that use `client` or a browser run (the others test Python code); tests marked `python_only` (they patch Python internals, e.g. the throttle's clock) are skipped, and the Go code has its own tests for them (`go test`, in `go/*_test.go`). Unlike the Python app under test, a Go server makes a plain `wiki_dir` a git repository at start (`gitSetup`); the `client` fixture starts it before the test, so its start-up (git, the deck's files) is done before the test looks, as Python's at import. `config.GIT_ENABLED = False` reaches it as a `PATH` without git; the browser tests' server restarts the moment a test sets a setting (a `__setattr__` on the `config` module), since requests made with `page.request` don't pass the route. The Python tests of internals (`mdtext`, `pages`, `decksyntax`) have a Go counterpart in golden files: `go/testdata/golden.py` runs 28 pure functions on every string literal in `tests/` (and some edge cases) and writes Python's answers to `golden.json.gz`, which `go/golden_test.go` checks Go against; rerun it after changing one of them while both exist.

`tests/test_git.py` uses `git_wiki_dir` and covers every git path (commit-on-write, history/revision/diff/restore, `_deleted`, uncommitted/commit endpoints, git-disabled fallbacks); it skips when git is not installed. The other test modules use the plain `wiki_dir`, so git calls there are silent no-ops.

`tests/test_mcp.py` covers the MCP server (with the fake semantic index too: read_page's related pages, a new page's pages close in content): the protocol handler, the HTTP transport and auth, the wiki-guide page in the instructions, folder guides (a write refused until their ids are passed, imports, a changed guide's new id, every page write gated, dry runs not; read_guides for a page, a folder and the wiki, the guided folders in its description, read_page's guide id), the reading tools (tasks created through `/api/deck`; with and without the fake semantic index from `test_semantic.py`; search_wiki's heading paths and its query log (only with `LEAF_QUERY_LOG`, rotation), read_page's links and one section, list_pages' link counts and orphans, check_links, list_tags, grep_wiki with regexes, limits, a bad pattern, the timeout and the no-git fallback, history: recent changes, a page's versions and a diff), and the writing tools: pages (create/overwrite, exact-text edit, find and replace across pages (dry run, code left alone, regex groups, a folder, the max_pages guard, a catastrophic regex stopped after the timeout with nothing written, plain text without a process of its own), append under a heading, rename with links, a folder move (subfolders, links, a page of its name, refusals), delete, similar-name and broken-wikilink notes) and tasks (create, update fields and status, id prefixes, comment, delete), several edits at once, restore_page (a version, a deleted page), a page open in the editor (its auto-saved draft committed first as the user's, the editor's 409 after), plus one commit per write marked `(MCP)`; and leaf_help over a small docs folder (passages for a query, a doc, a section, the topic list, testing.md left out, no docs installed) and over the real docs, which the image must copy.

`tests/test_task_refs.py` covers `[[task:…]]` references: chip rendering and badges (dates as `<time>` for the locale), done/won't-do/missing, recurring series, list rows, code, Linked tasks, search by task title and MCP `read_page`. `tests/e2e/test_task_refs.py` ticks chips (undo, keep tasks), the editor completion and Make task (the modal for one item, Cancel, batch mode for several lines with shared tags and per-line shorthand, headings skipped, inline selection, undo, the hidden deck leaving the editor's keys alone).

`tests/test_semantic.py` covers semantic search with a fake embedder (words mapped to a few "concept" axes), so it needs neither onnxruntime nor a model: chunking (heading paths), a cache of an older chunking re-chunked with its vectors kept, the search dialog's mode (off, indexing, on, failed: rendered and in `X-Leaf-Semantic`), the content-addressed cache, failure fallback, the worker, rank fusion, hybrid `/api/search` and the Related section. It swaps `retrieval.SEMANTIC` for an index over the temp wiki.

`tests/test_eval_retrieval.py` covers `tools/eval_retrieval.py`: a page target matching any section and a section target only its own, ranks by keywords on a temp wiki, targets naming nothing (page, section, task), the report's numbers per mode, the questions file's format (questions without targets skipped and counted), `--new`'s stubs from the query logs (known and repeated queries left out, newest first), and that the semantic index it builds never writes the wiki's cache.

`tests/test_env_example.py` checks `.env.example` against the settings the source, `run.sh` and `compose.yaml` read (none missing, none unknown).

`tests/test_run_sh.py` covers `run.sh`'s container calls and `.githooks/pre-commit` against a stub `podman` first on PATH (it logs its arguments; `run`/`start` exit with `FAKE_EXIT`), in a scratch git repo holding copies of both, so it needs no engine: `leaks` passes a temporary `GIT_INDEX_FILE` in as a `/repo/…` path (absolute or relative; outside the repo: exit 2), copy mode creates the container with `--rm`, a build's output stays hidden unless it fails (then nothing runs) and a first build says so, `test` and `e2e` run pytest in parallel (pytest-xdist), `eval` refuses a missing questions file and builds with `LEAF_SEMANTIC_SEARCH` and mounts the wiki read-only, and the hook scans the temporary index of `commit -a` and `commit <path>`, refuses a leak (exit 3) and only warns when the scan fails. The hook tests skip when a local gitleaks is on PATH.

To run the suite without a local venv: `./run.sh test` (runs inside the app image with the repo mounted).

Both `./run.sh test` and `./run.sh e2e` run in parallel with pytest-xdist: `test` with `-n auto` (a worker per CPU), `e2e` with a worker per two CPUs (each runs its own Chromium; at one per CPU the browsers starve and timing-sensitive tests fail). An `-n` in the extra args overrides it (`-n 0`: one process). Workers are separate processes: each has its own `LEAF_DATA`, temp wikis, server thread (`base_url`) and browser, so the fixtures need no locking; a test must keep its files under `tmp_path`.

## Browser tests (`tests/e2e/`)

End-to-end tests drive the real app in headless Chromium via Playwright. They run in a separate tools image (`Containerfile.tools`, based on Microsoft's Playwright image; it also has Node, gitleaks, and pngquant for the README's screenshots) so the app image stays browser-free and the app still has no build step or npm. `./run.sh e2e` builds that image (cached) and runs them in parallel (above) with the repo bind-mounted; extra args pass through to pytest (e.g. `./run.sh e2e -k deck`). Without Playwright installed they skip, so plain `pytest tests/` is unaffected.

- `conftest.py` serves `server.app` on a background thread (werkzeug `make_server`, random port) and points it at a fresh temp wiki with its own git repo per test; each test gets a fresh browser context. A request to any other host is aborted (offline, deterministic) and fails the test: Leaf loads nothing from a CDN. Uncaught page JS errors fail the test.
- Coverage: Scratch filter and the search dialog's mode indicator (its wording, its update from `X-Leaf-Semantic`, fitting on a phone; `test_search.py`), modules (breadcrumb switcher and current module, phone tab bar (a tap acts on the touch, no click of the browser's; a tap below the bar's box, as Firefox lays it out, still reaches the tab), New per module, due count on the Deck links, the deck home, desktop top actions, New task/`c t`/`g t` following the deck home; `test_mobile_nav.py`), side columns (sticky TOC and links from 1320px, active section, code and tables growing only when needed, none below 1320px; `test_layout.py`), editor (formatting bar and Ctrl+B/I/K, auto-save + unsaved dot, no commit on auto-save, Done/Ctrl+S commit, pagehide beacon, live preview/F2, list continuation), search modal (Ctrl+P/Esc, fuzzy ranking with file names and its tie-break, content matches, query syntax, highlights on the opened page, arrow/Enter nav, unlinked filter), deck (an undo armed only after its own write, Plan-board drag to a day and to Unplanned, touch long-press drag via CDP touch events (board, Open-tab reorder, swipe still scrolls, a long press let go in place starts selection mode, also where nothing drags, and moving after the hold cancels it), board grouping by start date, modal "Days before due", Plan board in Open's order with in-section drops ignored, view tabs, start-date Today, selection (Shift/Ctrl+click, Ctrl+A, the selection bar and the menu of a selection, the bulk tag dialog's three states and undo), touch: tap-to-edit, ⋯ menu/bottom sheet, selection mode (taps toggle, no drags, the bar in the tab bar's place, its ways out), target sizes, editor scrolling/compact phone layout, date picker placement), sortable tables (header click cycles ascending/descending/original, numeric columns, empty cells last, keyboard, not in the editor preview), layout (no horizontal page scroll at 390px phone width on page/editor/deck views, mobile Preview button, tldr toggle geometry (and the open text lined up with the row beside the side columns), the heading copy-link icons), the Content-Security-Policy (a page's `<script>`, `onerror=` and `javascript:` link and the editor preview's handler don't run, an uploaded `.js` doesn't run as a script; `test_security.py`).
- Density: the test setup (`_new_page`'s init script) makes decks open with full cards, as before the per-tab defaults, since most tests exercise cards; a test of the real defaults calls `real_density(page)` first.
- Touch: `new_page(**TOUCH_PHONE)` gives a phone context with touch input, `hover: none` and `pointer: coarse` (use `.tap()`). Full-page screenshots of such a context lose the touch/hover emulation (Playwright re-renders with changed device metrics), so assert on computed styles/sizes rather than on a full-page image.
- `test_screenshots` writes full-page PNGs of each view at phone/desktop × light/dark to `tests/e2e/_screenshots/` (gitignored) for visual review. It asserts nothing about appearance.
- Playwright's HTML5 drag cannot auto-scroll mid-drag, so drag tests must keep source and target on screen (e.g. enlarge the viewport).
- Keep the `playwright==` pin in `Containerfile.tools` equal to the image tag version.
- Content-Security-Policy: Leaf's pages run under `script-src 'self'` (Security in `docs/spec/security.md`). The harness collects the violations Chromium reports on the console (`page.csp_violations`) and fails a test that has any, so new code can't bring in an inline script or handler unnoticed; a test that blocks one on purpose (`test_security.py`) clears the list. Under that policy Playwright can't `eval` in the page: `page.wait_for_function` needs a function (`"() => scrollY > 0"`), as an expression string is evaluated with `eval`; `page.evaluate` works either way.

`tests/test_deck_core.py` exercises the pure client logic in `src/public/deck-core.js` (the locale's date helpers too) by running it under Node (`node -e`); those tests skip automatically when Node is not installed. The app image has no Node, so `./run.sh test` (and CI's test job) skips them; `./run.sh e2e` (and CI's e2e job) runs them, since the tools image (`Containerfile.tools`) installs Ubuntu's `nodejs`.
