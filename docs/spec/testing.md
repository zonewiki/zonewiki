# Tests

Part of Leaf's spec (see `AGENTS.md` for the index).

How the suite is set up and what each module covers. The rules (run it, add tests with every change) are in `AGENTS.md`.

## Shared setup

`tests/conftest.py` holds the shared setup: every test gets a fresh temp wiki (`wiki_dir`: just `index.md`, `_assets/` and `_deck/`; `git_wiki_dir`: the same set up as a git repository, as Leaf does at start; `client`, a server on it), plus helpers that modules import from `tests.conftest`: `HOST`, `write_page`, `create_task`, `contentHash`, `section_fields` (the editor's hidden fields for a section, read from its `/edit` page), `preview` (markdown as `/api/preview` renders it), `rendered` (a page's article), `backlinks` and `task_backlinks` (a page's link sections). The browser tests' `wiki` fixture builds on `git_wiki_dir`.

**The server under test** (`tests/goserver.py`): the binary is built once per run (`go build` in `go/`, by pytest's first process, which hands the path to the xdist workers in `LEAF_TEST_BINARY`). The `client` fixture is a `GoClient`: it takes the calls of Flask's test client (get/post/put/delete with headers, data, json, query_string; cookies) and sends them over HTTP to a server started on the test's wiki, answering with werkzeug's `TestResponse` (`get_json()`, `get_data(as_text=True)`, `status_code`, `headers`). The browser tests' `wiki` fixture starts one on a port fixed for the session. The settings a test changes in `tests/settings.py` (`monkeypatch.setattr(settings, "LEAF_PASSWORD", …)`: `LEAF_HOSTS`, `LEAF_LOCALE`, `NOSHARE_TAGS`, `GIT_ENABLED` (a `PATH` without git) …) reach the server in its settings file, `.leaf/config` (`config_text` in `goserver.py`: the settings that differ from Leaf's defaults, passwords and tokens as their hashes, then `settings.CONFIG_FILE`, more of the file's text, then the users as `[user …]` sections; written before the server starts, and removed once the settings give none), the deployment's (`LEAF_ALLOW_REMOTE`, `settings.ENV`) as its environment): when they change, it restarts on the same wiki (and port) before the next request; the browser tests' server restarts the moment a test sets one (a `__setattr__` on the module), since requests made with `page.request` don't pass `_new_page`'s route. Leaf's docs folder (`settings.DOCS`, which `TestLeafHelp` points elsewhere) reaches it as `-docs`; the semantic index (`settings.SEMANTIC`, a `tests/semantic.py` `FakeIndex`) as `-semantic-test`: the server gets the fake concept embedder and floors (`go/embedtest.go`), syncs once at start when the test called `sync()`, and restarts after each `sync()`, so it sees the wiki as it is then. A server makes the wiki a git repository at start (`gitSetup`), so `git_setup(tmp_path_factory)` (a server started and stopped) is how a test "restarts Leaf" (start-up commits, `index.md`, the yearly archives). What no route reaches (text functions, search ranking, the index's cache, git helpers, the protocol's limits) has Go tests in `go/*_test.go`; `go/testdata/golden.json.gz` holds the answers of the Python Leaf's text functions on every string in its tests, which `go/golden_test.go` checks the Go ones against; after a deliberate change to one of those functions, `LEAF_GOLDEN_UPDATE=1 go test -run TestGolden` (in `go/`) logs every case that changed and writes the new answers.

`tests/test_git.py` uses `git_wiki_dir` and covers every git path (commit-on-write, history/revision/diff/restore, `_deleted`, uncommitted/commit endpoints, git-disabled fallbacks); it skips when git is not installed. A server makes any wiki a repository when it starts, so the other modules' wikis are repositories too; `settings.GIT_ENABLED = False` gives the server a `PATH` without git, for the fallbacks.

`tests/test_mcp.py` covers the MCP server (with the fake semantic index too: read_page's related pages, a new page's pages close in content): the tool definitions (names, hints, their size, which take guides), the HTTP transport and auth, the wiki-guide page in the instructions, folder guides (a write refused until their ids are passed, imports, a changed guide's new id, every page write gated, dry runs not; read_guides for a page, a folder and the wiki, the guided folders in its description, read_page's guide id), the reading tools (tasks created through `/api/deck`; with and without the fake semantic index from `test_semantic.py`; search_wiki's heading paths and its query log (only with `query-log`, rotation), read_page's links and one section, list_pages' link counts and orphans, check_links, list_tags, grep_wiki with regexes, limits, a bad pattern, the timeout and the no-git fallback, history: recent changes, a page's versions and a diff), and the writing tools: pages (create/overwrite, exact-text edit, find and replace across pages (dry run, code left alone, regex groups, a folder, the max_pages guard, a regex RE2 can't take refused), append under a heading, rename with links, a folder move (subfolders, links, a page of its name, refusals), delete, similar-name and broken-wikilink notes) and tasks (create, update fields and status, id prefixes, comment, delete), several edits at once, restore_page (a version, a deleted page), a page open in the editor (its auto-saved draft committed first as the user's, the editor's 409 after), plus one commit per write marked `(MCP)`; and leaf_help over a small docs folder (passages for a query, a doc, a section, the topic list, testing.md left out, no docs installed) and over the real docs. The protocol's handling (versions, notifications, errors) and the limits long answers are cut at are `go/mcp_test.go`'s.

`tests/test_task_refs.py` covers `[[task:…]]` references: chip rendering and badges (dates as `<time>` for the locale), done/won't-do/missing, recurring series, list rows, code, Linked tasks, search by task title and MCP `read_page`. `tests/e2e/test_task_refs.py` ticks chips (undo, keep tasks), the editor completion and Make task (the modal for one item, Cancel, batch mode for several lines with shared tags and per-line shorthand, headings skipped, inline selection, undo, the hidden deck leaving the editor's keys alone).

`tests/test_semantic.py` covers semantic search through the server with a fake embedder (words mapped to a few "concept" axes, `tests/semantic.py`), so it needs neither onnxruntime nor a model: the search dialog's mode (off, indexing, on, failed: rendered and in `X-Leaf-Semantic`), hybrid `/api/search` and the Related section. The index itself (chunking with heading paths, a cache of an older chunking re-chunked with its vectors kept, the content-addressed cache, failure fallback, the worker, rank fusion, settings, the model's download) is covered by `go/embed_test.go`.

`go/eval_test.go` covers `leaf eval`: a page target matching any section and a section target only its own, ranks by keywords on a temp wiki, targets naming nothing (page, section, task), the report's numbers per mode, the questions file's format (questions without targets skipped and counted), `-new`'s stubs from the query logs (known and repeated queries left out, newest first), and that the semantic index it builds never writes the wiki's cache.

`tests/test_image.py` checks the Containerfiles: the model's revision and hashes are the ones `go/embed.go` checks, the semantic layer copies nothing from the repo (a code change mustn't download the model again), both images build with the same Go, and the image ships the browser code and the docs.

`tests/test_env_example.py` checks `.env.example` against the settings the source, `run.sh` and `compose.yaml` read (none missing, none unknown; the variables of settings that moved into the settings file, which the code names only to refuse and import them, don't count).

`tests/test_routes.py`'s `TestMergeOnSave` covers merge on save over HTTP (different lines merged, the same lines 409 with the markers, the fallbacks, a section's new range, saving on from the text sent, set aside, Keep mine committing what was never in git, Done merging and committing); `tests/e2e/test_merge.py` two editors (alice and bob, two browser contexts) in the browser: a merge into the textarea (the note, the cursor, one undo), typing on while a merged answer comes back, and the banner's Merge by hand (auto-save waits for the markers), Reload theirs and Keep mine, also after Done; `go/merge_test.go` covers `mergeText` (clean, the same change on both sides, no final newline, an empty base, conflict markers, no git) and the bases kept. `tests/test_users.py` covers users: signing in per user (the name field, wrong name or password, throttling, a removed user and a switch from one password to users signed out), per-user MCP tokens, commit authors (browser, deck, uploads, scratch notes, MCP; Leaf's own commits and a wiki without users), authors in the history and on deck comments and History events (an undo keeps them), and another user's draft committed in their name before a save, Done, checkbox, delete, rename, Commit file/all or MCP write (`TestDrafts`). `settings.LEAF_USERS` maps a name to its password and token; `goserver.py` writes their hashes into the settings file (`password_hash`: a fixed salt and few iterations, so the server's settings stay the same between requests and logins are quick). `tests/test_privacy.py` is the leak test for private pages and tasks: alice's private page (committed, deleted, uncommitted), scratch note, upload, deck home, list and private tasks hold a word that no response to bob, signed in or through his MCP token, may contain, and bob's writes must leave her files alone. It probes every route and MCP tool; `test_every_route_is_covered` and `test_every_tool_is_covered` fail for a route Leaf registers, or a tool it offers, that is neither probed nor exempt: a new one gets a probe there. `go/access_test.go` covers the rules themselves (`canSee`, `canSeePath`, `hiddenPage` with sharing mode, `strayPrivate`), `go/deckstore_test.go` the per-user deck files (`canSeeTask`, `mayMakePrivate`). `go/users_test.go` covers the hash format and `authenticate`; `go/security_test.go` the session's user.

`tests/test_config.py` covers the settings file through the server: a new user signs in without a restart, a removed one is signed out, a changed password (ending the old one's sessions) and MCP token, a broken file keeping the settings from before (alice stays in, no one else gets in) and failing `/api/health` until it is fixed (the error itself only with a session), a file without users and password kept until a restart, other settings reloading, the wiki's password as a hash, a setting left in the environment stopping Leaf, the file committed at start and on a reload (its tokens only as hashes, the message naming what changed) but never served or shown in history and the uncommitted list, an older wiki's exclude line replaced, and a new wiki's first commit without the session key. Leaf looks at the file at most once a second, so a test that rewrites it waits that out (`write`) rather than polling logins, which the throttle would count. `go/configfile_test.go` covers the parser (every error and its line), the settings from the file (defaults, every check), the reload (kept on an error, a removed file, at most once per `reloadEvery`, the noshare cache), the line edits keeping comments, the 0600 write, `leaf user` and `leaf config` on a temp wiki (`set`/`unset`, `passwd`, `token`, `import` from an older environment), token hashes, the commit message (`settingsChange`), and `leaf health` failing on the error.

`tests/test_run_sh.py` covers `run.sh`'s container calls and `.githooks/pre-commit` against a stub `podman` first on PATH (it logs its arguments; `run`/`start` exit with `FAKE_EXIT`), in a scratch git repo holding copies of both, so it needs no engine: `leaks` passes a temporary `GIT_INDEX_FILE` in as a `/repo/…` path (absolute or relative; outside the repo: exit 2), copy mode creates the container with `--rm`, a build's output stays hidden unless it fails (then nothing runs) and a first build says so, `test` runs go vet and go test before pytest, `test` and `e2e` run pytest in parallel (pytest-xdist), `eval` refuses a missing questions file and builds with `LEAF_SEMANTIC_SEARCH` and mounts the wiki read-only, and the hook scans the temporary index of `commit -a` and `commit <path>`, refuses a leak (exit 3) and only warns when the scan fails. The hook tests skip when a local gitleaks is on PATH.

To run the suite without a local Go or venv: `./run.sh test` (go vet, go test, then pytest, inside the tools image with the repo mounted).

Both `./run.sh test` and `./run.sh e2e` run in parallel with pytest-xdist: `test` with `-n auto` (a worker per CPU), `e2e` with a worker per two CPUs (each runs its own Chromium; at one per CPU the browsers starve and timing-sensitive tests fail). An `-n` in the extra args overrides it (`-n 0`: one process). Workers are separate processes: each has its own temp wikis, servers (`base_url`) and browser, so the fixtures need no locking; a test must keep its files under `tmp_path`.

## Browser tests (`tests/e2e/`)

End-to-end tests drive the real app in headless Chromium via Playwright. They run in the tools image (`Containerfile.tools`, based on Microsoft's Playwright image; it also has Go, Node, gitleaks, and pngquant for the README's screenshots) so the app image stays browser-free and the app still has no build step or npm. `./run.sh e2e` builds that image (cached) and runs them in parallel (above) with the repo bind-mounted; extra args pass through to pytest (e.g. `./run.sh e2e -k deck`). Without Playwright installed they skip, so plain `pytest tests/` is unaffected.

- `conftest.py` starts a server per test on a fresh temp wiki with its own git repo (on a port fixed for the session); each test gets a fresh browser context. Tests of how the editor behaves over a slow connection (`test_editor.py`'s `slow_saves`) put a small proxy between the browser and the server that answers auto-saves 2.5 seconds late. A request to any other host is aborted (offline, deterministic) and fails the test: Leaf loads nothing from a CDN. Uncaught page JS errors fail the test.
- Coverage: Scratch filter and the search dialog's mode indicator (its wording, its update from `X-Leaf-Semantic`, fitting on a phone; `test_search.py`), modules (breadcrumb switcher and current module, phone tab bar (a tap acts on the touch, no click of the browser's; a tap below the bar's box, as Firefox lays it out, still reaches the tab), New per module, due count on the Deck links, the deck home, desktop top actions, New task/`c t`/`g t` following the deck home; `test_mobile_nav.py`), side columns (sticky TOC and links from 1320px, active section, code and tables growing only when needed, none below 1320px; `test_layout.py`), editor (formatting bar and Ctrl+B/I/K, auto-save + unsaved dot, no commit on auto-save, Done/Ctrl+S commit, pagehide beacon, live preview/F2, list continuation), search modal (Ctrl+P/Esc, fuzzy ranking with file names and its tie-break, content matches, query syntax, highlights on the opened page, arrow/Enter nav, unlinked filter), deck (an undo armed only after its own write, Plan-board drag to a day and to Unplanned, touch long-press drag via CDP touch events (board, Open-tab reorder, swipe still scrolls, a long press let go in place starts selection mode, also where nothing drags, and moving after the hold cancels it), board grouping by start date, modal "Days before due", Plan board in Open's order with in-section drops ignored, view tabs, start-date Today, selection (Shift/Ctrl+click, Ctrl+A, the selection bar and the menu of a selection, the bulk tag dialog's three states and undo), touch: tap-to-edit, ⋯ menu/bottom sheet, selection mode (taps toggle, no drags, the bar in the tab bar's place, its ways out), target sizes, editor scrolling/compact phone layout, date picker placement), sortable tables (header click cycles ascending/descending/original, numeric columns, empty cells last, keyboard, not in the editor preview), layout (no horizontal page scroll at 390px phone width on page/editor/deck views, mobile Preview button, tldr toggle geometry (and the open text lined up with the row beside the side columns), the heading copy-link icons), folding sections (a click, nested folds, Alt+click and `z`, the wavy line and its "folded" that unfolds, anchors/TOC/hashchange/`beforematch`/search highlights unfolding, `]` skipping folded headings, presentation and print, the chevron's place on desktop and phones; `test_fold.py`), the Content-Security-Policy (a page's `<script>`, `onerror=` and `javascript:` link and the editor preview's handler don't run, an uploaded `.js` doesn't run as a script; `test_security.py`).
- Density: the test setup (`_new_page`'s init script) makes decks open with full cards, as before the per-tab defaults, since most tests exercise cards; a test of the real defaults calls `real_density(page)` first.
- Touch: `new_page(**TOUCH_PHONE)` gives a phone context with touch input, `hover: none` and `pointer: coarse` (use `.tap()`). Full-page screenshots of such a context lose the touch/hover emulation (Playwright re-renders with changed device metrics), so assert on computed styles/sizes rather than on a full-page image.
- `test_screenshots` writes full-page PNGs of each view at phone/desktop × light/dark to `tests/e2e/_screenshots/` (gitignored) for visual review. It asserts nothing about appearance.
- Playwright's HTML5 drag cannot auto-scroll mid-drag, so drag tests must keep source and target on screen (e.g. enlarge the viewport).
- Keep the `playwright==` pin in `tests/requirements.txt` equal to `Containerfile.tools`' image tag version.
- Content-Security-Policy: Leaf's pages run under `script-src 'self'` (Security in `docs/spec/security.md`). The harness collects the violations Chromium reports on the console (`page.csp_violations`) and fails a test that has any, so new code can't bring in an inline script or handler unnoticed; a test that blocks one on purpose (`test_security.py`) clears the list. Under that policy Playwright can't `eval` in the page: `page.wait_for_function` needs a function (`"() => scrollY > 0"`), as an expression string is evaluated with `eval`; `page.evaluate` works either way.

`tests/test_deck_core.py` exercises the pure client logic in `public/deck-core.js` (the locale's date helpers too) by running it under Node (`node -e`); those tests skip automatically when Node is not installed. `./run.sh e2e` (and CI's e2e job) runs them, since the tools image (`Containerfile.tools`) installs Ubuntu's `nodejs`; `./run.sh test` leaves them to it.
