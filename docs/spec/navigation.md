# Navigation, modules and scratch

Part of Leaf's spec (see `AGENTS.md` for the index).

## Page List

- `GET /pages` redirects to `/`. The search/browse UI lives in a modal dialog, not a dedicated page.
- **Search modal** — opened via the "Search" nav button or **Ctrl+P** (⌘P on Mac), closed with **Esc** or clicking the backdrop.
  - Backdrop click detection: `e.target === searchModal` (not coordinate comparison — coordinates break with `<select>` dropdowns).
  - Page data is loaded lazily on first open from `GET /api/pages-list` (JSON: slug, title, links, mtime) and cached for the session. Each list item shows the page title and slug — dates are not shown in the modal.
  - Filter input instantly narrows the list by title/slug (`titleMatch`: the better `fuzzyScore` of the title and the **file name**, the slug's last part scored on its own, so a file name starting with the query counts as a match at the start; a match reaching into folder names only scores `FOLDER_PENALTY` less, since ".../2026-05-26_alex-1on1/prep" is not the page "alex" names); after 150ms debounce fetches `/api/search` for full-text **Content matches** with excerpts shown below the page list.
  - **Several words** (`wordsScore`): each must fuzzy-match within one word of the title or file name, and all must match; the scores add up. Matching the whole input as one letter sequence let "alex again" find its letters spread over "Add alert exporter tag handling". A single word still matches across the whole title.
  - **Ties** in the fuzzy score are common (every title starting with the query scores the same), so `tieBreak` orders them: scratch notes last, then fewer folders in the slug, then the shorter name. "alex" lists the top-level `alex-morgan` before notes three folders down and the scratch note `…_alex_prep`, instead of alphabetically.
  - **Sort by** — Recently edited (default, so an empty query works as a quick switcher), Title A–Z, Title Z–A, Most linked. Applies while the query is empty; a sort picked by hand is remembered in `localStorage` (`leaf-search-sort`).
  - **Built-in pages** — `api_pages_list()` adds Deck (`href: /deck`), Scratch and (git only) Deleted Pages, marked `builtin`. Deck and Scratch are modules, linked from the module switcher, so the empty-query list leaves them out; Deleted Pages, also marked `special`, is pinned above the pages whatever the sort, set apart by a stronger rule (`.page-list-special`). Typing matches all three like any other entry; "Unlinked only" leaves them out.
  - **Unlinked only** checkbox — pages with zero incoming wikilinks, in the title list and in the Content matches: the modal sends `/api/search?…&unlinked=1`, and the server keeps only such pages, no tasks (`do_search(unlinked=True)`, same counts as the list's, `all_backlink_counts`) before it cuts the results to 15. Toggling it re-runs the content search.
  - First match is highlighted (with no title match, the first content match once it arrives); **↑/↓** moves the highlight across both page results and content match cards; **Enter** opens the highlighted item.
  - **Preview pane** (≥1100px; `showModalPreview` in `js/search.js`): the modal widens (up to 1180px, 76vh) into results on the left and the highlighted result on the right. A page comes from `GET /api/page-preview/<slug>` (`{title, html}`: rendered without its H1, heading ids as `data-pid` so they don't clash with the page underneath, deck embeds as *(deck)*; cached per slug while the page is open), scrolled to the result's `#anchor` section, its `hl` words marked (`markTerms`, shared with the opened page's highlights). A task, the deck or a built-in page shows its result card. Updates 80ms after the highlight settles.

## Modules

Leaf has three modules, in this order: the **Wiki** (pages, home `/`), **Scratch** (scratch notes, `/page/_scratch`) and the **Deck** (`MODULES` in `views.py`). The Deck link goes to the **deck's home**, the page whose embed says `home=1` (your own deck, e.g. `[[deck list=task view=focus home=1]]`; `pages.lookup_deck_home()`, from the deck embeds' params cached per page in `_page_meta_cache`, first slug A–Z; `deck_home_slug()` looks it up once per request), else to `/deck` (`_module_href`). `/deck` stays the view of every task that search results, task links and `g d` open. There is still no nav bar: the modules sit where the eye already goes.

- **Current module**: `current_module()` names each view's (`/deck` and the deck's home page → deck; `/page/_scratch`, a scratch note and its history → scratch; `/search` and `/login` → none; everything else → wiki), and `layout.html` puts it on `<body data-module>` (not in the editor). The server marks the matching `.module-link`s `aria-current="page"` (`views.module_links`), so the highlight is there at first paint.
- **Module switcher** (`switch` in `templates/partials/modules.html`, `.breadcrumb-home.module-switch`): the root of every breadcrumb, leaf logo + Wiki, Scratch, Deck. On desktop it is set apart from the trail as a control: a bordered pill group with the current module shaded, and the first separator drawn as a thin vertical divider instead of `›` (`.module-switch + .breadcrumb-sep`). On phones and in the editor only the logo shows (the way home). The navigation trail leaves out the modules' own pages (`index`, `_scratch`, `/deck` and the deck's home, whatever the Deck link points at).
- **Top actions** (desktop, `templates/partials/top_actions.html`, `.top-actions`, first in `<main>`): at the top right of the page, in line with the breadcrumb (absolutely positioned in `main`; the breadcrumb gets `min-height: 2.25rem` and right padding so its own end stays clear), in three groups: **Sharing mode** (`.top-sharing`, the eye, `aria-pressed`; see Sharing mode), set apart by a divider (`.top-sep`) since it switches a mode; the two "new" icons, **New scratch note** (`.top-scratch`, `openScratch`, `c s`) and **Add a task to your deck** (`.top-task`, `openHomeTask`, `c t`; a checkbox with a +, so it doesn't read as "done"); and **Search** (`.top-search`, Ctrl+P), the one used most, as a labelled pill with its shortcut (`.top-search-key`, `⌘P` on a Mac). Icons are 2.25rem, muted, a background on hover; name and shortcut in tooltip and accessible name. The pill has a fixed width, so the row's width (`--top-actions-w`, which the breadcrumb's padding and the status badges' position use) doesn't depend on the font; its border ends on the content's right edge. Hidden at ≤640px. They replaced the round New and Search buttons in the bottom-right corner, so desktop toasts and Sign out have the bottom corners to themselves again.
- **New task from anywhere** (`openHomeTask` in `js/actions.js`, the `.top-task` button and `c t`): the task goes to the deck's home, tagged as it tags new tasks (`decksyntax.new_task_tags`: its `list=` tag, then the single tags of `tag=`) and a keep task if it says `keep=1`. On the home page it clicks the home embed's own **+ New** (so the view's dates apply too, e.g. Focus's today); anywhere else it opens a deck app's edit modal with the home's tags, keep and start (`layout.html` puts them on `<body>`: `data-deck-tags`, `data-deck-keep`, `data-deck-today` when the home's view is Focus, as its "+ New" starts tasks today there; without a home, today, as `/deck`'s Focus; `openEditModal` takes `tags`, which replace the filter's even when empty, `keep` and `start_date`): the page's own deck app (an embed, `/deck`, the editor's hidden one), or on a page without one a hidden one loaded on demand (`loadHeadlessDeck`: `GET /api/deck/headless`, the headless embed without its scripts, then `deck-core.js` and `deck.js`; once per page), so you stay on the page and a toast says "Added “…” to your deck". Should loading fail, the home page (or `/deck`) opens with `?new=1`. Without a home the task gets no tags. **g t** goes to the deck's home (`deckHomeHref`: where the Deck module link points, else `/deck`).
- **Action bar** (`action_bar` in `templates/partials/modules.html`, `nav.action-buttons`): the phone's: three groups set apart by dividers (`.action-sep`), as on desktop: the three modules (`.action-module`); the desktop's two "new" actions with the same icons (`icons.new_note`, `icons.new_task`), **Note** (`.action-scratch`, a new scratch note, `openScratch`, `c s`) and **Task** (`.action-task`, a new task); and **Search** (`.action-search`, Ctrl+P, `openSearchModal`). Navigation and actions apart, so the "new" buttons say what they make instead of a bare +. Hidden on desktop (the top actions). At ≤640px it is a bottom tab bar across the full width: Wiki · Scratch · Deck | Note · Task | Search, icon over label, the current module in the accent green, each at least 44px. The Deck tab's counts stand right of its icon, due above Focus, centred on the icon; they reach past the tab into extra room before the divider (its `margin-left` while counts show), so they cover neither the icon nor the divider, and the tabs keep one width, the icons evenly spaced. `views.page(…, action_buttons=False)` omits it, and the editor and the login page leave it out. On phones it is hidden via CSS `:has()` whenever an input/textarea/select has focus, because the on-screen keyboard owns the bottom edge then, and `main` gets extra bottom space so the bar never covers the page's end. A tap on the bar acts on its `touchend` (`item.click()`) and cancels the browser's own click (`preventDefault`; a long press over 500ms or a move over 10px is left to the browser). Firefox for Android as an installed app, its toolbar scrolled away, draws the bar lower than it lays it out, so a tap on the strip under the labels landed below the bar's box, on the page (on the deck a card, selected and scrolled into view). So the tab is found by position, in capture listeners on `document` before the page sees the touch: a touch on the bar, or below its box where nothing covers the bar (`elementFromPoint` at its bottom edge; a menu's bottom sheet or a dialog does), goes to the tab nearest its x.
- **Task** (`js/actions.js`): in the deck module it clicks the deck's own **+ New** (`#task-add-btn`, the home embed's (`data-home`) on the home page), so the view's tags and dates apply; elsewhere it adds a task to your deck as `c t` does (`openHomeTask`). A new page is Ctrl+N on desktop; on a phone, a scratch note and its **Move to wiki**.
- **Counts**: the Deck links (switcher and tab bar) carry two counts (`.module-counts`): tasks due today or overdue (`.module-due`, orange) and tasks in Focus (`.module-focus`, muted; `DeckCore.isFocus`: started, or due today or earlier), each hidden at zero, with a tooltip like "Deck: 5 in Focus · 1 overdue · 1 due today". `deck.deck_counts()` counts the deck home's tasks, its `list=` and `tag=` (`decksyntax.tag_param_matches`, the server's reading of `tag=` as deck.js has it), or every task without a home. The server renders them into the page (`views._deck_counts`, once per request, into `partials/modules.html`), since filling them in by a fetch after the page had painted made the link change width on every load (flicker); `refreshDueBadge` in `js/chrome.js` refreshes them from `/api/deck/due-count` every minute, on tab focus, on a back/forward-cache restore and after deck writes (`deck.js` calls it). They replaced the separate due badge at the top left.
- **Status badges** (`.top-badges`: uncommitted count, and Sign out when auth is on; the first thing in `<main>`, after the remote 🌐 `.remote-badge`, which on desktop sits left of the module switcher, in the margin outside the content's edge, on the row's centre line, and in the editor at the top right): on desktop they sit in the top row, left of the top actions, centred on the row (the breadcrumb keeps their room free; Sign out, though inside, is fixed to the bottom-right); in the editor fixed at the top right, since its breadcrumb starts at the window's left edge. The row aligns to `main`'s side padding (`--main-pad`): the switcher starts on the content's left edge, the search pill ends on its right edge. At ≤640px they join the page flow above the breadcrumb, so they no longer cover it, Sign out on the right of that row (the bottom edge is the tab bar's), and 🌐 is hidden, since on a phone remote access is a given. The deck's due count is on the Deck module links (see Modules).

## Sharing mode

For sharing the screen: the page on screen stays as it is, everything that shows *other* pages around it is hidden, and pages not for sharing are left out entirely. Switched by the eye in the top actions or **S** (Shift+s; `toggleSharing` in `js/actions.js`). The state is a cookie (`leaf-sharing=1`, a year), so the server knows it: `layout.html` renders `<html class="sharing">` from the first paint (nothing flashes on load), and switching reloads the page, rendered for the new mode. While on, a thin amber bar runs across the top and the eye is highlighted. Phones have no switch (no top actions).

- **Around the page** (`html.sharing` in `style.css`): the breadcrumb's trail of visited pages (`js/chrome.js` marks it `.trail-link`/`.trail-sep`; the separator left before the page becomes the divider), the backlinks chip, Backlinks / Linked tasks / Related / Links to (side column and `.page-foot`), a section's linked-task chips, the status counts (deck counts on the Deck links, uncommitted badge). The search modal lists nothing until something is typed (no recent pages; nothing for ↑/↓ or the preview to reach), and the editor's `[[` page and task completion waits for two letters.
- **Pages not for sharing** (`LEAF_NOSHARE` in `.env`: comma-separated, `#tag` entries name frontmatter tags, `folder/` entries folders and everything below them, e.g. `LEAF_NOSHARE=#noshare,#people,people/,personal/`; a bare word counts as a tag; unset or empty: `#noshare`; don't quote the value). `is_noshare(slug)` (folders by slug, tags from the frontmatter, cached by mtime), `hidden_page(slug)` = sharing mode on and noshare. Such a page's view, editor, history, revisions and diffs (`/diff`, `/diff-uncommitted`) show "Hidden page" (`hidden_page_view()`: neither title nor text, no trail stop); `/api/page-preview` 404s; search (`do_search`: `/api/search`, `/search`, the Scratch filter), `/api/pages`, `/api/pages-list`, the Scratch list, Deleted Pages, the uncommitted list, Backlinks, Links to and Related leave them out; a wikilink to one renders as its words without the link (`<span class="wikilink-hidden">`). The MCP tools are not a browser and ignore sharing mode.

## Scratch

- **Keybinding:** **c** then **s** creates a scratch note (see Keyboard Shortcuts); so does the phone's action bar's Note (see Modules).
- User types a title and submits → `POST /api/scratch` → server creates `<YYYY-MM-DD_HH-MM-SS>_<slug>.md` (local time) with `# Title\n\n` and returns `{ slug }` → browser navigates to `/edit/<slug>`. The editor opens with the cursor under the title, ready for the body, as for a brand-new page: a page that holds only its `# Title` line (`only_title` in `edit_page`, `data-cursor="end"` on the textarea) starts with the cursor at its end; any other page at its start.
- A `<dialog id="shortcuts-modal">` lists all keybindings, opened with `?`.
- **Scratch note filenames** match `SCRATCH_RE = r"^\d{4}-\d{2}-\d{2}_\d{2}-\d{2}-\d{2}_(.+)$"` e.g. `2026-03-24_18-50-08_my-note.md`. `is_scratch(slug)` identifies them.
- **`/page/_scratch`** — special auto-generated page (no `.md` file on disk) listing all scratch notes newest-first with title and timestamp. Not editable.
  - **Filter** (`#scratch-filter`, `initScratchFilter` in `js/search.js`): a box above the list that runs the search over scratch notes only (`/api/search?scratch=1`, `do_search(scratch=True)`), so ranking, stemming, typos, semantic hits and the query syntax (`"phrase"`, `-word`, `#tag`, `edited:` …) are the search's. Matches show in ranked order with their excerpt (marked), linking to the matching section with `?hl=` highlights, plus a count ("2 of 30"); everything else is hidden. `scratch=1` lifts the limit to `SCRATCH_FILTER_LIMIT` (1000), so every match is listed. The query is kept in `?q=` (`history.replaceState`), so Back returns to the filtered list and `/page/_scratch?q=…` links work. Enter opens the first match; Esc clears the box (a second Esc leaves it); an empty box restores the newest-first list. No filter when there are no notes.
- **Move to wiki** (the scratch note's ⋯ menu, `#page-promote-dialog`, `promote_dialog` in `templates/partials/page.html`; `POST /promote/<slug>`): gives the note a real name, so it leaves Scratch. The dialog asks for a **folder** (a `<datalist>` of the existing ones, `page_folders()`), the **name** (pre-filled with the note's title, not its timestamped slug; a `/` in it is a hyphen) and whether to **keep the date** (`YYYY-MM-DD_` in front of the name, as in `conversations/2026-07-08_…`), and previews the slug (`promotedSlug` in `js/pagemenu.js` mirrors `promoted_slug()`, `toSlug` mirrors `to_slug`). **Link from** names the page to link it from, since a page in the wiki is almost always linked from somewhere; `js/pagemenu.js` fills in the folder's `index` page while one exists, until you edit the field; empty means no link. With one, Move first copies the new page's link (`[[slug|Title]]`, `page_wikilink`) to the clipboard (`copyText`: the Clipboard API, or the copy command where it isn't available, as on plain http on the LAN; the form's `copied` field says whether it worked), and after the move that page opens in the editor (`/edit/<page>?paste=<slug>&copied=1`) with a hint (`.paste-hint`, `paste_hint_html`): one row of a clipboard icon, "Link copied. Paste it where it belongs on this page." over the link (one line, cut off with …), Copy and ×, so you paste it where it belongs; the page itself isn't changed. A page that already linked to the note (its link now following) opens the moved page instead. The page fields of both dialogs suggest from one `<datalist id="wiki-pages">` (`wiki_pages` from `views.page_menu`: every page but scratch notes) and take a slug, `/page/<slug>` or a name (`page_from_input`). It is a rename underneath: links to the note follow (`update_references`), one commit `Promote <old> to <new>`, which the history calls "Moved from Scratch". An empty name, a taken one or one that would still be a scratch name goes back to the note with `?promote_error=…` and the dialog open.
- **Append to page** (the scratch note's ⋯ menu, `#page-append-dialog`, `append_dialog` in `templates/partials/page.html`; `POST /append/<slug>`): for a note that belongs on an existing page (meeting notes on a person's page). The dialog asks for the page (the shared `#wiki-pages` suggestions) and the section heading (`Title (YYYY-MM-DD)`, `_append_heading`; `[`, `]` and `|` are dropped, they would break wikilinks to it). `note_as_section()` makes the note a `## heading` section: its H1 goes, a tldr becomes an italic first line, its headings move down so the highest is `###` (fenced code untouched); its frontmatter tags join the page's (`add_frontmatter_tags`, adding the line or block). The section goes at the end of the page, the note is deleted (so Deleted Pages can restore it), and links to it point at the section (`update_references(old, new, section)` → `rewrite_page_links(…, section=)`: a link with its own `#anchor` keeps it, since the note's headings keep their text), pages and deck tasks alike, in one commit `Append <note> to <page>`; the page's history calls it "Scratch note appended". Refused (no page, the note itself, no heading, a heading the page already has) → back to the note with `?append_error=…`, the dialog open.
- Daily notes (`/api/daily`, `/page/_daily`, `c d`/`g y`) were removed on purpose. Existing `YYYY-MM-DD_daily.md` files are ordinary pages.
- **`/page/_deleted`** — special auto-generated page listing all pages that exist in git history but not on disk (deleted pages), newest deletion first. Each entry shows title, slug, deletion date, and a one-click Restore button that calls `POST /restore/<slug>/<sha>`. Only available when `GIT_ENABLED`. Navigating to a deleted page's URL directly also shows a restore prompt instead of redirecting to the editor.
- Appears in the search modal as a synthetic entry injected by `api_pages_list()` with title "Scratch" (found by typing; the empty-query list leaves it out, see Page List) — matches searches for "scratch" or "_scratch". `_deleted` is similarly injected with title "Deleted Pages" (git only). A "Deck" entry (slug shown as `/deck`) links to the built-in deck page; entries may carry an `href` for targets that are not `/page/<slug>`.
- Special pages (starting with `_`) are not filtered out of the search modal or backlink counts but are treated as regular pages otherwise.

## Keyboard Shortcuts

Defined in the `keydown` listener in `js/shortcuts.js`. Bare-key shortcuts are suppressed when focus is inside an `input`, `textarea`, `select`, or `[contenteditable]`.

|----------|---------|--------|
| **Ctrl/⌘+P** | anywhere | Open search modal |
| **Ctrl/⌘+N** | anywhere | Open new-page modal |
| **g** then **h/s/d/t** | anywhere | Navigate: Home / Scratch / Deck (every task) / your deck (the deck's home) |
| **c** then **s/t** | anywhere | Create: scratch note / task in your deck (tagged as it tags new tasks) |
| **F2** | editor | Toggle preview pane |
| **Ctrl/⌘+S** | editor | Done — commit and go to page view |
| **Ctrl/⌘+B / I / K** | editor | Bold / italic / link (see Formatting bar) |
| **Ctrl/⌘+Shift+X** | editor | Toggle checkbox on current line |
| **Ctrl/⌘+Delete** | page view | Delete current page (confirmation dialog) |
| **S** | anywhere | Sharing mode on/off (see Sharing mode) |
| **e** | page view | Navigate to edit mode |
| **]** / **[** | page view | Next / previous section (`##`/`###`, not a deck embed's; `jumpSection` in `js/shortcuts.js`): scrolls it to the top and puts its anchor in the URL; the current one is the last heading scrolled past, as the side TOC marks it; `[` before the first goes to the top |

## Presentation Mode

- **Present** is in the page's ⋯ menu (see Page header) whenever the page has a heading.
- Choosing Present (or pressing **`p`**) opens a fullscreen dark overlay, splitting the article into slides at each `<h2>` boundary.
- Content before the first `<h2>` (if any) becomes an intro slide.
- Navigation: **← →** arrow keys, or click "← Prev" / "Next →" buttons. **Esc** exits.
- The slide counter (`1 / N`) is shown in the centre of the control bar.
- Slide content re-uses `.page-content` CSS so typography, code blocks, and links render correctly inside the overlay. CSS custom properties are overridden to force dark colours.
- Syntax highlighting is re-applied via `hljs.highlightElement` when each slide is shown.
- The Present menu item is hidden (via JS, `syncPresentBtn`) on pages with no headings.
