# Users

Part of Zone's spec (see `AGENTS.md` for the index).

Several people on one wiki: each signs in with their own name and password, their changes are committed in their name, and an assistant connected with their MCP token acts as them. Everything in the wiki is shared and editable by every user, except each user's private folder, `private/<name>/`, and their private tasks, which only they see.

Users are `[user NAME]` sections of the wiki's settings file, `.zone/config` (below). Without them none of this applies: one password (or none) and one MCP token, and Zone commits as itself.

## In short

Three rules; the rest of this file is how they are kept.

1. **Your folder is yours.** `private/<you>/` holds your private pages, your uploads (`_assets/`) and your private tasks (`_tasks/`). No one else sees it in Zone, in search, in history, or through their assistant. Everything outside it is shared, and every user may change it. (Hidden inside Zone, not encrypted: whoever has the wiki's folder or git repository has it all.)
2. **Where something is kept is who sees it.** Not its tags, not its links, not its name. A new page or task starts where it is made: from a link to `private/<you>/…`, an embed on a private page, your private pinned list or list.
3. **Private can be shared; shared stays shared.** A private page goes public by Make shared (a rename out of the folder), a private task by unticking its Private box. Never the other way: others have seen a shared page or task, link to it and have comments on it, so Zone refuses to take one into a private folder or tasks (the error says to make a new private one and copy the text). Making a page shared takes the uploads it shows with it. Nothing else moves anything.

## The settings file

The wiki's settings and its users are in `.zone/config` in the wiki, a small INI read by Zone's own parser (`go/configfile.go`; no dependency). Zone reloads it when it changes, so nothing here needs a restart. `.env` holds only the deployment (`docs/spec/deployment.md`).

```ini
# Zone's settings and users (docs/spec/users.md). Zone reloads this file when it changes.
locale = de-AT
hosts = wiki.example.org, nas.local
noshare = #noshare, people/

[user alice]
password = pbkdf2-sha256:600000:<salt>:<hash>
mcp-token = sha256:<the token's SHA-256, hex>
role = admin

[user bob]
password = pbkdf2-sha256:600000:<salt>:<hash>
disabled = yes
```

| Key | Does | Default |
|-----|------|---------|
| `password` | The login gate without users: a hash (`zonewiki config passwd`) | no login |
| `mcp-token` | Turns on `/mcp` without users: the token's hash (`zonewiki config token`) | `/mcp` off |
| `hosts` | Names Zone may be reached by besides localhost, comma-separated (the Host check, `docs/spec/security.md`) | localhost only |
| `base-url` | Zone's address as the browser knows it, for links handed to AI clients (`docs/spec/mcp.md`) | the address the request came in on |
| `git-remote` | A remote for the wiki's repository; `origin` is set to it (`setGitRemote`) | none |
| `noshare` | Pages hidden in sharing mode: `#tags` and `folders/` (`docs/spec/navigation.md`); empty: none | `#noshare` |
| `locale` | How dates read and the day weeks start on, a BCP 47 tag like `de-AT` (`docs/spec/tasks.md`) | US English dates, weeks from Monday |
| `date-format` | `iso`: dates as `YYYY-MM-DD` | the locale's |
| `query-log` | `yes`: keep `search_wiki`'s queries in `.zone/queries.jsonl` (`docs/spec/search.md`) | no |
| `semantic-min-score` | How similar a passage must be to be a semantic hit, -1 to 1 (`searchFloor`, `docs/spec/search.md`) | the model's floor |
| `trusted-proxies` | Reverse proxies whose `X-Forwarded-For` names the client, IP addresses or networks (`172.17.0.1, 10.0.0.0/8`), for the throttle on wrong passwords (`clientKey`, `docs/spec/security.md`); empty: none | loopback (`127.0.0.0/8, ::1`) |
| `upload-max` | The biggest upload, a size (`25MB`; below) (`Settings.uploadMax`, `docs/spec/security.md`) | 100 MB |
| `storage-max` | How much the wiki may hold, a size (`5GB`): past it, nothing new is made (Storage limit, below) | no limit |

- **Format**: `key = value` (spaces optional), the wiki's settings before the first section, a `[user NAME]` section per user with `password`, `mcp-token`, `role` and `disabled` (`configKeys`, `userKeys`; Roles, below). `#` starts a comment only at the start of a line, so `noshare = #noshare` is a value.
- **Sizes** (`upload-max`, `storage-max`; `parseSize` in `go/storage.go`): bytes (`300`), or a number with KB, MB, GB or TB, any case, a space optional, decimals too (`1.5GB`). They count by 1024, as Zone's caps always have (100 MB is 100 × 1024 × 1024 bytes). Empty is unset; 0, or a unit Zone doesn't know, is an error.
- **Storage limit** (`storage-max`, `go/storage.go`): what counts is every file in the data directory but `.git/` and Zone's own `.zone/` (the settings file, the session key, the search cache): the user's pages, uploads (`_assets/`, `private/<user>/_assets/`), tasks and any other files there. Not the history: a deleted file still in git frees its space, and the history, mostly text, is the host's to plan for. Zone walks the directory only when a write asks for room, and then at most once a minute (`usedBytes`; a walk reads names and sizes, no contents: 20,000 files take about 10 ms); an upload or a new page adds its size at once (`added`), so uploads in a row can't slip past. A figure that says full is walked again first, but at most every 5 seconds (`usageRecheck`), so a client asking over and over in a full wiki doesn't make a walk each time: a file deleted on disk counts within seconds, a page deleted through Zone at once (`forgetUsage`). Refused once it would go past (`checkRoom`, `refusedFull`: 507 Insufficient Storage, "The wiki is full: 5.0 GB of 5 GB used. Delete pages or files to make room."; an MCP tool's error): an upload (its size, less the file's it replaces: a smaller file replacing one always fits), a new page (`/new`, the editor opened on a page that doesn't exist yet, its first save, `write_page`), a new note (`/api/notes`, `write_page` with `note`). Never refused: an edit to a page, even one that grows it (typed text is never turned away), a restore, a rename or move, a delete, Move to wiki and Append to page (a note's text moves), tasks (small, and capped per request). The browser shows the refusal of an upload or a new note (`alert`); the editor never opens on a new page, so nothing typed is refused.
- **Errors name their line** (`.zone/config line 3: "pasword" isn't a setting Zone knows.`), and Zone won't start on one: a key it doesn't know (a typo shouldn't leave Zone on a default), a value that doesn't check (`localeRE`, `parseNoshare` …; `query-log` takes yes/no, 1/0, true/false), a section other than `[user NAME]`, a user's key outside a section or the wiki's inside one, a key or a section given twice, a line that isn't `key = value`, `password` or `mcp-token` of the wiki together with users (each has their own; a shared one would make the user unknown). Messages never repeat a password or token.
- **Passwords are kept as hashes**, never in plain text: PBKDF2-SHA256 with a random 16-byte salt and 600,000 iterations (`hashPassword`; Go's own `crypto/pbkdf2`), written `pbkdf2-sha256:<iterations>:<salt>:<hash>` (base64 without padding); checked at sign-in by `checkPassword`.
- **MCP tokens are kept as hashes** too, `sha256:` and 64 lowercase hex digits (`hashToken`, `isTokenHash`): the commands make a token (32 random bytes, hex), show it once and keep only its hash; Zone compares the SHA-256 of the token a client sends (`tokenMatches`, constant time). A token is random, so its hash is no use to whoever has the repository. A plain token in the file is an error.
- **The file is committed**, the rest of `.zone/` isn't (the session key, caches, the query log): `.git/info/exclude` has `/.zone/*` and `!/.zone/config` (`excludeState`, also before a new wiki's first commit; an older Zone's `/.leaf/` line is replaced, also written `/.leaf`, `.leaf/` or `.leaf`, or without a final newline). Before Leaf was called Zone the folder was `.leaf/`: Zone moves it at start-up (The data directory in `docs/spec/deployment.md`). Zone commits it, as itself, at start and after each reload that took a change, the message naming what changed by name and key only (`commitSettings`, `settingsChange`: `Change settings: add user carol, alice's password, locale`); the commands leave git to Zone (one process), so their change is committed when a running Zone reloads it, else at its next start.
- **Zone never shows it**, since it holds password hashes: `canSeePath` is false for `.zone/` for everyone, so history, the uncommitted list, Commit all and the MCP tools leave it (and a commit of nothing else) out, and `safePath` refuses it to every page route and MCP tool. Whoever has the repository or the git remote has the hashes: PBKDF2 at 600,000 rounds is made to withstand that, but a weak password can still be guessed offline.
- **Writing**: the commands and the Users page (Managing users, below) write it owner-only (0600), whole, to a temporary file in `.zone/` synced and renamed over it (a reload never reads half a file), one command at a time (`lockFile` on `.zone/config.lock`, flock) and only onto the file as the command read it (changed meanwhile, by another command or an editor: "not changed: … Run it again."), keeping the comments and order of the lines they don't change (`go/internal/settingsfile`: `File.Set`, `Unset`, `RemoveUser`, `Write`). Zone logs a warning when others may read it.
- **Settings left in `.env`**: until 2026-10 these were environment variables (`LEAF_PASSWORD`, `LEAF_MCP_TOKEN`, `LEAF_USERS` with `LEAF_USER_<NAME>_PASSWORD`/`_MCP_TOKEN`, `LEAF_HOSTS`, `LEAF_BASE_URL`, `LEAF_GIT_REMOTE`, `LEAF_NOSHARE`, `LEAF_LOCALE`, `LEAF_DATE_FORMAT`, `LEAF_QUERY_LOG`, `LEAF_SEMANTIC_MIN_SCORE`), and `LEAF_SECRET_KEY` set the session key. Any of them still set stops Zone at start, naming them (`staleEnv`): ignored, a forgotten `LEAF_PASSWORD` would leave the wiki open. `./run.sh config import` moves them into the file (a plain password and the MCP tokens as their hashes, so the clients keep their tokens; users as sections) and lists the lines to delete from `.env`.

### Commands

The file can be edited by hand, or with the commands; a running Zone takes each change within a second:

```bash
./run.sh user add alice                # asks for her password twice
./run.sh user add bob --mcp-token      # also makes him an MCP token, shown once
./run.sh user passwd alice             # a new password
./run.sh user token bob                # a new token; the old one stops working at once
./run.sh user add carol --role viewer   # admin, editor (the default) or viewer; the first user is an admin
./run.sh user role carol editor        # change a role
./run.sh user disable bob              # he can't sign in, his token stops; user enable bob undoes it
./run.sh user remove bob               # his private pages and tasks stay on disk
./run.sh user remove alice --password  # the last user: the wiki's password instead (or --open: no login)
./run.sh user list                     # the users, their roles (but editor), who has a token, who is disabled
./run.sh config set hosts nas.local    # any other key of the table; config unset KEY for its default
./run.sh config unset password         # no login (a running Zone takes it only at a restart)
./run.sh config passwd                 # without users: the wiki's password
./run.sh config token                  # without users: the wiki's MCP token, shown once
./run.sh config check                  # what's wrong, or each setting in effect and where it comes from
./run.sh config import                 # the settings from an older .env into the file
```

- Without the container it is `zonewiki user …`, `zonewiki config …` with `ZONE_DATA` set (`go/commands.go`: `userMain`, `configMain`); on a NAS, through the container: `docker compose -f compose.nas.yaml run --rm zonewiki /app/zonewiki user add alice`. `run.sh` runs the binary in a one-off container of the app's image (`compose build -q leaf`, its output only on failure, then `compose run --rm --no-deps leaf /app/zonewiki …`), with `.env` and the wiki mounted as `up` has them, so the file is written as Zone's user and `config import` sees `.env`; the password prompt's echo is off (`echoOff`, the container has a terminal; `-T` when stdin isn't one).
- They refuse a change Zone wouldn't start with ("not changed: …", the file as it was): a user who is there already (add) or isn't (the others), a value that doesn't check (or isn't one line), `config passwd`/`token` with users (each has their own), `config set password`/`mcp-token` (those have their commands; `config unset` takes them out: no login, `/mcp` off).
- **Between a password and users**: the first `user add` replaces the wiki's `password` and `mcp-token` (with users each has their own) and says so; the last user goes only with `user remove NAME --password` (asks for the wiki's password, set in the same write) or `--open` (no login), else it is refused: without users private/ is an ordinary folder everyone sees, and without a password the wiki has no login.
- **Never back to no admin**: once the wiki has an admin (not disabled), a change that would leave it without one is refused, whether it removes, demotes or disables the last ("that leaves the wiki without an admin. Make another user admin first": `keepsAdmin`, in `saveConfig`, so every command keeps to it). Taking the last user out (`--password`, `--open`) is no such change: without users there is no one to manage. An edit by hand isn't checked: it stays the way out.
- `config check` lists each setting, its value (passwords and tokens only as `(set)`) and where it comes from (`[line 3]`, `[default]`), and the users; it fails on an error in the file and on settings left in the environment.
- **Names**: lowercase letters, digits and inner hyphens (`userNameRE`), since a name becomes a folder name. A user's MCP token is optional: without one they have no MCP access.

### Reloading

The request checks (`checks` in `go/server.go`) call `reloadSettings`, which looks at the file at most once a second (`reloadEvery`: its time, size and whether it is still the same file, as an editor may replace it); a change reads it again. No file watcher. The git work after a change (`applySettings`, `commitSettings`) runs outside the lock (`takeSettings`), so the other requests don't wait for git. The settings are held behind an atomic pointer (`settings()`, `Settings`); what is fixed for the process stays in `cfg`. **A change takes effect between requests**: the checks count the requests running (`beginRequest`, `endRequest`), and a change takes effect only while none is running (`betweenRequests`): at once when none is, else from a goroutine when the last one ends; until then requests go on with the settings before, so nothing waits for the change, and a newer change replaces one still waiting. So a request sees one set of settings from its session check to its answer: else one whose session was checked against the users before the change could be judged by the ones after (a switch from users to a password makes `private/` an ordinary folder, for a user who no longer has a login). A request still running after 10 s (`drainWait`: a slow download) doesn't hold the change up longer; the log says so.

- **A file with an error** on reload: Zone keeps the settings it has, logs the error with its line, and `GET /api/health` answers 503 with it (without a session: only that there is one, see the log, as it may name users), so `zonewiki health` (the container's healthcheck) fails until the file is fixed. A broken edit never locks everyone out or opens the wiki. A file removed while Zone runs counts the same (taking the users away would open the wiki): Zone keeps its settings until the file is back, or a restart. So does a file that takes the login away, no users and no password where there were (by hand, `user remove --open` or `config unset password`): only a restart takes that, on purpose.
- **What a reload changes**: a new user signs in at once; a removed or disabled user is signed out with their next request (the session must name a current user, not disabled); a new role applies from the user's next request; a changed MCP token takes effect at once, the old one refused. A changed password ends the sessions signed in with the old one (`passwordStamp`, below), the user's own included. Users ↔ no users signs everyone out, as `signedIn` checks. A new `git-remote` re-points `origin` (`setGitRemote`); a new `noshare` clears its cache; the file is committed (above). Throttles, caches and the search index stay.

## Roles

Each user has a role, `role` in their section (`roles`, `User.Role` in `go/users.go`):

| Role | Can |
|------|-----|
| `admin` | everything an editor can, and manage the users (`zonewiki user`, on the host) |
| `editor` | change everything shared, as every user could before roles: the default, so a section without `role` is an editor's |
| `viewer` | read what is shared; change only their own private folder. **Not enforced yet**: for now a viewer changes what an editor does (`docs/plans/user-admin.md`, phase 4) |

- **The first user is an admin**: `user add` on a wiki without users writes `role = admin` and says so, unless `--role` says otherwise. So one person running their own wiki is its admin without doing anything. Every other user is an editor unless `--role` says otherwise. A wiki from before roles has no admin until `zonewiki user role NAME admin` makes one; nothing else changes for it.
- **An admin isn't a superuser**: no admin sees another user's private pages, tasks or notes, or knows their password. Rule 1 above holds for everyone.
- **Disabled** (`disabled = yes`, `zonewiki user disable NAME`): the user can't sign in (with the right password the login says "Your account is disabled. Ask an admin of this wiki.", with a wrong one the usual "Incorrect user name or password.", and both count as a wrong try for the throttle), their sessions stop working at their next request (`signedIn`), and their MCP token is refused (401; `mcpAuthorized`; a disabled user's token alone doesn't turn `/mcp` on). Their pages, tasks and private folder stay as they are. Enabled again, they sign in as before, and a session from before not yet expired works again: disabling isn't how to end a stolen session, a new password is (Signing in, below). A disabled admin counts as no admin.

## Managing users

**The Users page** (`/users`, `go/admin.go`, `users.html`) is the admins' way to manage users in the browser, as `zonewiki user` is on the host. "Users" in the user menu opens it (phones: beside Sign out at the top), shown to admins only; for anyone else, and in a wiki without users, `/users` and every change below is a 404, as for a page that isn't there.

- **The list**: each user's name, "(you)", "MCP" if they have a token, their role, and Active or Disabled. Then the invite form, the open links (Invite and reset links, below) and what the roles mean.
- **Per user**: change their role (a select and Change), **Disable** or **Enable**, **Reset password** (makes a link), **Remove…** (a `<details>` that says what happens, then **Remove NAME**: their private pages, notes and tasks stay in `private/NAME/`, seen by no one, and someone added again under that name gets them back; an open link of theirs goes too). There is no field to type another user's password: the admin never knows it.
- **Plain forms, no JavaScript**: each change is a POST (behind the Origin check, like every write). Done, it answers with a redirect to `/users?done=…&user=…`, and the page says what was done from a fixed set of messages, so a link can't make it say anything else. Refused, the page comes back (409) saying why. An admin who demoted, disabled or removed themselves is sent to the home page.
- **The same rules as the commands**: the page edits the settings file with `go/internal/settingsfile` and saves it with `saveConfig` (checked, locked, only onto the file as read: a change made meanwhile by hand or a command is never overwritten), so a change that leaves the wiki without an admin is refused here too. The last user can't be removed here: without users the wiki has no login, which is for the host (`zonewiki user remove NAME --password` or `--open`).
- **Taken at once, committed by the admin**: after the write Zone reloads the file at once (`changeSettings`), not within the second; the change takes effect once the requests running (the admin's own too) have ended (Reloading, above), and the page lists the users as that change has them (`latestSettings`). Its commit names the admin as author (`Change settings: bob's role`, `settingsAuthor`).

## Invite and reset links

A link that lets one person set a password, once (`go/links.go`). Zone sends no mail: the admin copies the link and sends it any way they like.

```bash
./run.sh user invite dave --role viewer   # an invite: the link, shown once
./run.sh user reset alice                 # a new password for alice
```

- **Made** on the Users page (Invite someone: a name and a role; Reset password beside a user) or with `zonewiki user invite NAME [--role ROLE]` / `zonewiki user reset NAME`. The page shows the whole address (with `base-url`'s, else the address the admin's request came in on), the command `base-url`'s or the path alone. An invite is for a name no user has, a reset for a user there. While an invite is open its name is taken: `user add` of it is refused.
- **Kept** as the token's hash only (`hashToken` of 32 random bytes, as an MCP token), with the user's name, invite or reset, the role, who made it and when it expires, in `.zone/links`: owner-only (0600), written whole, one change at a time (`changeLinks`: a lock in the process and `lockFile` on `.zone/links.lock`, as a command may write it too), not committed (state, like the session key: the rest of `.zone/` is excluded from git).
- **Valid** 7 days (an invite) or 24 hours (a reset), **once**. A new link for the same name replaces the old one; **Revoke** on the Users page (open links: for whom, what, by whom, until when) deletes it. Expired links go at the next change.
- **Capped**: 10 links per admin in an hour (`linksPerHour`, in memory), so a stolen session can't fill the list.
- **The welcome page** (`/welcome/<token>`, `welcome.html`; no login needed): opening it changes nothing, since mail scanners and chat previews open links. It greets the invitee by name (or says whose password it sets) and asks for a password twice ("Choose a password.", "The passwords differ."). Only its POST uses the link: an invite adds the user with its role, a reset sets the new password, which ends every session of the old one (`passwordStamp`); either way the change is committed in that user's name, the link is gone, and they are signed in (a session made with the new hash, `setSessionHash`, as the settings take effect only once the request has ended). A user who was removed (reset), or a name someone took meanwhile (invite), is refused, as is a wiki that has no users any more. The page sends `Referrer-Policy: no-referrer`: its address holds the token.
- **A link that doesn't work**, wrong, used, expired or replaced, gets one page for all ("This link doesn't work", 404), and a client trying them is throttled as for wrong passwords (`welcomeThrottle`).
- **No minimum length** for the password, as `user add` has none.

## Signing in

- The login page asks for the user name and the password (`login.html`; the name field only with users). The name is compared in lower case, without surrounding spaces. A wrong name or password says "Incorrect user name or password." (not which one), keeps the name typed, and costs the same time either way: an unknown name is checked against a dummy hash (`authenticate`), so timing doesn't tell which names exist. Wrong tries are throttled per client as with the wiki's one password (`loginThrottle`, see `docs/spec/security.md`); not per user name, which would let anyone lock a user out.
- **The session names its user** (`session.User` in the signed cookie, `signedIn`). With users, a session must name one of them; without, it must name no one. So removing a user signs them out, and switching between one password and users signs everyone out. It also carries a stamp of the password it was signed in with (`session.Pw`, `passwordStamp`: a MAC of the password's hash, which has its own salt): a new password, or the same one set again, or a user removed and added again, ends every session of the old one, so changing a password is how to sign out a stolen session. (Sessions from before the stamp count as the old password's: everyone signs in once.)
- **The request knows its user**: the request checks (`checks` in `go/server.go`) put the session's user into the request's context (`withUser`), `userOf(r)` reads it, and `newReq` keeps it as `rq.user`. "" means no users (or no one signed in).
- The user's name is shown beside Sign out (`.signout-user`, "Signed in as alice") on phones, in the page's top row. On desktop both are in the user menu (below): the form is hidden there (`.signout-user-menu`).

## MCP

With users, `/mcp` takes any user's token (`mcp-token` in their section) and the tools run as that user (`mcpAuthorized` returns the user, `callMCPTool` passes it to every tool). `/mcp` is off (403) while no user has a token; a wrong token is a 401 and throttled as before (`docs/spec/mcp.md`).

An assistant sees and changes what its user does in the browser, no more (`docs/spec/mcp.md` has the tools):

- **Another user's private page is no page**: `read_page`, `edit_page`, `append_to_page`, `rename_page`, `delete_page`, `file_note` answer "No page …" for it, as for a page that doesn't exist (`mcpPageSlug(raw, user)`, `existingPage`). A new slug in `private/` outside your own folder (`write_page`, a rename's or a restore's target, `history` or `read_guides` of a page there) is refused with "of private/, only your own folder private/<you>/ is yours to read or write", whether or not anything is there (`newSlug(raw, user)`, `notYours`).
- **Lists and searches leave them out** (`visiblePages(user)`, `visibleSlugs`): `list_pages` (and its link counts), `search_wiki` (`retrieve(rq, …)` filters before the limit), `grep_wiki` (`grepPages` takes the visible slugs; the hits are counted after), `check_links`, read_page's "Broken links" and the "new links point to pages that don't exist" note of every write (a link into another user's folder is never reported broken, whether or not the page is there, and never suggested: `missingLinks`, else "no such page" would tell which private pages exist), `list_tags`, `replace_in_pages` (matches and changes only pages you may change), read_page's Linked from and Related, delete_page's "still link to it", write_page's similar pages, create_task's tag hints.
- **History**: `history` of a page as `pageLog` gives it (versions from before a page was yours are left out); recent changes (`history` without a slug) show of each commit only the files you may see and leave out a commit with none of them, asking git for more until `limit` are found (`gitLogAll(…, see)`); the uncommitted files likewise. A commit message naming another user's private page (`Promote private/alice/…_idea to idea`) names it "a private page" (`hideNames`), here and in the browser's history. `restore_page` takes only versions `pageLog` lists.
- **Notes** from `write_page` with `note` go to your folder (its guides apply: `checkGuides` with `private/<you>/note`).
- **Tasks**: the tasks tools see the shared tasks and the user's own private ones (Private tasks below): another user's private task is "No task with id …" to `update_task`, absent from `search_tasks`, `list_tags`' counts, `search_wiki`, read_page's `[[task:…]]` list ("no such task") and create_task's tag hints. `create_task` and `update_task` take `private` (true: the user's own; false: shared; refused without users); `create_task` makes a private task by default when the user's default task list is in their private folder, as `c t` does. The task text says "private" among its facts.
- **Guides**: a `CLAUDE.md`/`AGENTS.md` in another user's folder isn't a guide for you (`folderGuides(slug, user)`, `canSeePath`), not listed in read_guides' description (`toolList(user)`), and a guide's `@import` of a page you can't see stays as written (`guideText`). `rename_page` of a folder holding pages you may not move (`private/` itself) moves nothing.

## Private pages

Pages in `private/<name>/` (and its subfolders) are that user's: only they see and change them. Make one from a link to it (`[[private/alice/diary]]` on one of your pages: the missing link opens its editor), by moving a note there (Move to wiki, folder `private/alice`), or by linking to it from a private page (below); on a private page `[[` completion offers a new private page (Wikilink autocomplete in `docs/spec/editor.md`); `/new` (the form without JavaScript) has a **Private** box too (`private=1` puts the slug in your folder; the box shows only with users). Rename it out of the folder, or use **Make shared** in its ⋯ menu, to share it. **There is no way to make a shared page private** (rename, Move to wiki, `rename_page` and a folder move all refuse: "a shared page stays shared"): others have seen it, and the pages that link to it would lose their links. Create a new page in your folder and copy the text. A new page is made private from the start (below).

- **Private home** (`go/private.go`): `/private` opens `private/<you>/index`, the hub of your own sub-wiki, and makes it on the first visit from a small template (`# Private`, a line that the pages in your private folder are hidden from the other users of this wiki, a `## Links` heading; committed in your name, `Create private/<you>/index`). It is an ordinary page: edit it, link your private pages from it (a missing `[[link]]` on it opens the editor), put what you like on it. Like the wiki's own `index`, it can't be renamed or deleted (`isProtected`: 400 in the routes, "can't be …" from `rename_page` and `delete_page`); should it vanish anyway, `/private` makes it again. Signed out it goes to the login; without users there is no private home (404, and `private/<x>/index` is an ordinary page).

- **Lock** (🔒, `.lock`): a private page shows it beside its title, in the search modal's page list (`private` in `/api/pages-list`) and on its search results (the result's meta starts with 🔒, `resultMeta`); shared pages and wikis without users show none.
- **Make shared** (the ⋯ menu of your own private page, `sharedMove` in `go/private.go`, `#page-privacy-dialog`): moves it out of your folder (`private/alice/notes/x` → `notes/x`). The dialog says where it goes and that everyone who uses the wiki then sees and changes it, and submits the ordinary rename (`POST /rename/<slug>` with `from=page`: links re-point on pages and in tasks, the uploads it shows are copied to `_assets/` (Uploads, below), one commit `Rename <old> to <new>`; a refusal such as "A page named … already exists" comes back in the Rename dialog). Not offered without users, for a shared page, another user's page, the wiki's home or a private home, or a note (Move to wiki takes those out of the folder).
- **Shared stays shared** (`refuseMakingPrivate`, `sharedIntoPrivate` in `go/pages.go`): a rename, Move to wiki (also of an old shared note from before users), an assistant's `rename_page`, a folder move, that would put a shared page into a private folder (yours, or no one's: `private/carol/…`) is refused before anything moves, with "it is shared, and others have seen it: a shared page stays shared". In the browser the rename dialog (and the editor's rename bar) comes back with the name typed and that error. Links therefore never have to be unlinked: a move *out* of a private folder re-points the links of your own pages and tasks, and of the shared pages that linked to it (marked 🔒 for you, below), in the rename's one commit.
- **A link from a shared page to your private page** (typed or pasted) is allowed, but marked for you (`.wikilink-private`: a 🔒 after it, tooltip "Links to a private page: others see plain text"; the live preview too): other users see plain text there. `[[` completion on a shared page, and in a shared task's title or notes, doesn't offer your private pages (a private task's does).
- **A new shared page from a private page** (`processWikilinks`' `from`, `sharedNewOffer` in `go/private.go`): on a page in your private folder a link to a page that doesn't exist and isn't private is marked (`.wikilink-shared-new`: a 🌐 after it, tooltip "Creates a shared page"; the live preview marks them too, the editor sending `?page=` to `/api/preview`) and carries `?from=private` (`/page/<slug>?from=private`, kept by the redirect to `/edit/<slug>?from=private`). That editor (a new page only) shows a note above the text, **🌐 This new page is shared: everyone who uses the wiki will see it. For a private page, link to `private/<you>/<name>` instead.**, with **Keep shared** (just dismisses it, not remembered). To make it private, change the link (`[[` completion on a private page offers a new private page, or write the path); there is no button that moves a shared page in, because a page never saved has nothing to move and the link you clicked would stay. No note when the page is private already, a private page of that name exists, there are no users, or the link was on a shared page.
- **Private** is a module (`docs/spec/navigation.md`, Modules): in the switcher's first pill, Wiki · Private (the pages; Tasks · Notes, the tools, are the second), with a small lock as Notes has (`.module-lock`, tooltip "Private: only you see it"), and a tab on phones; **g p** goes to Private home. Private views (a page in your folder, the home included) make it current, notes make Notes current. **The user menu** holds who is signed in and **Sign out** (desktop; phones have them in the page's top row). It opens from the **user button** (`.top-user`, a round initial with the name as its tooltip) at the top right, after Search.
- **What "private" means**: hidden inside Zone, from other users and their assistants. Not encrypted, and not hidden from whoever has the wiki's folder or its git repository: the files, their history and a git remote hold everything. Search's keyword index (BM25) is made of the shared pages and tasks alone (`indexCache`); a user's own private ones are added to it for them (`Index.WithExtra`: their document count, frequencies and lengths join the shared ones at query time, so they rank exactly as if one index held what they see), while another user's words, counts and lengths take no part in anyone's ranking, nor in the vocabulary that prefix and typo matching draw on (else a typo that stops matching would tell that a word is in a private page). The semantic index holds every page's vectors, but a search looks only at the visible ones (pages, sections, tasks, Related, and the pages a new page is compared with). The query log (`query-log`) is the wiki owner's file in `.zone/`, never shown in Zone: with users it holds every user's queries and the private pages they found.
- **The rule lives in one place** (`go/access.go`): `pageOwner(slug)` (the user, and whether the page is private at all), `canSee(user, slug)`, `canWrite(user, slug)` (the same pages: everything shared is editable), `canSeePath(user, rel)` for files as git names them (pages, and a user's uploads and tasks in `private/<user>/_assets/` and `_tasks/`, which the private folder covers). Names compare in lower case, and a path is judged as it is opened, cleaned (`private/bob/../alice/x` is alice's). Without users nothing is private, and `private/` is an ordinary folder.
- **No one's pages**: anything under `private/` outside a user's folder (a page in `private/` itself, `private/alice.md` beside the folder, the folder of a user no longer there) is seen by no one; Zone logs each such entry when it starts (`strayPrivate`), so the admin can move it.
- **Opening another user's page** (view, editor, history, a version, a diff, the search preview) is a plain 404, the same as for a page that doesn't exist, for every slug in their folder (`refusePage`), so it doesn't tell what exists there. Sharing mode's "Hidden page" stays for pages `noshare` hides.
- **Changing another user's page** is refused the same way, 404 (`canWrite`; `refuseWrite` in the routes): save and auto-save, new page, rename, delete, restore a version, toggle a checkbox, commit one file. Renaming a page *into* another user's folder goes back to the dialog with an error ("that folder is another user's"), as does Move to wiki into one; Append to page and Move to wiki's "Link from" take only pages you may change ("There is no page …"). Renaming a shared page to another shared place re-points links on every page, other users' private ones too, in one commit (Rename in `docs/spec/editor.md`); renaming one into your private folder is refused (Shared stays shared, above).
- **Notes are private**: with users the New note dialog says "New private note" and "Only you see it, until you move it to the wiki"; a new note goes to the top of your folder, `private/<you>/<timestamp>_<name>` (`createQuicknote`, `privateFolder`); Notes lists only yours, under a 🔒 like a private page (an empty Notes says "Notes are private: only you see them, until you move one to the wiki"; `listQuicknote`, `inQuicknote`; so do Notes filter and `list_pages`/`search_wiki` with `scratch`). A top-level note from before users stays a shared page: it opens by its link and shows in search and the page list, but is not in anyone's Notes (move it into your folder, or use Move to wiki). Move to wiki and Append to page take a note out of your folder (to the folder you name, the top level by default; to the page); an old shared note (from before users) Move to wiki'd into your private folder is refused, like a rename (Shared stays shared, above). `isQuicknote` takes a note at the top of a user's folder (not deeper, not in no one's folder, and without users only top-level notes).
- **Uploads** for a private page are private: the editor sends the page's slug with an upload (`page`, `markdownEditor`'s `page` option), and a file for a page in your own folder is kept in `private/<you>/_assets/` (`uploadDir`; URL `/private/<you>/_assets/<file>`, the folder's own path); any other page's uploads go to `_assets/` as before. `GET /_assets/<file>` serves `_assets/<file>` (a file straight in it, no subfolder), and `GET /private/<user>/_assets/<file>` only to that user (404 for anyone else, and for any other subfolder). **A page taken out of your folder takes the uploads it shows with it** (`shareUploads`, in the rename's commit): each `/private/<you>/_assets/<file>` it links, outside code, is copied to `_assets/` (your other pages keep their own; a name taken by a different file there gets `-2`, `-3` …) and the page points at the copy.
- **History and commits**: a page's history, its versions and diffs leave out versions from when the page was another user's private page, before a rename (`pageLog`, `canSeePath` on the version's path). The uncommitted list shows, and Commit all commits, only files you may see (`visibleUncommitted`): another user's draft stays uncommitted until they commit it.
- **Everywhere else** another user's private pages are left out as sharing mode leaves out pages not for sharing (`hiddenPage(rq, slug)`, which checks both; see Sharing mode in `docs/spec/navigation.md`): search, the search modal's list, Notes, Deleted Pages, the uncommitted list, Backlinks, Links to, Related, folder suggestions, link counts (the search modal's, "unlinked" in search: `allBacklinkCounts(rq)` counts links only from pages you may see); a wikilink to one renders as its words without a link.
- **Tests**: `tests/test_privacy.py` gives alice a private page (committed, deleted, uncommitted), a note, an upload, her own pinned list and list, and private tasks (open, completed, archived; one a shared page refers to with `[[task:…]]`), holding a word no response to bob may contain, and probes every route and MCP read tool as bob, and every write route and MCP write tool (her files and the commits must stay as they were); a route Zone registers, and an MCP tool, must be probed or listed as exempt there (`test_every_route_is_covered`, `test_every_tool_is_covered`). Further tests there cover what alice does with her own (notes, uploads, a new private page, history, Commit all, private tasks and their defaults); the Go tests in `go/taskstore_test.go` the per-user task files.

## Private tasks

A task can be private: only its user sees it, on every task list, in search, on pages and to their assistant. A new task is made private by ticking **Private** in the edit modal (it shows only with users); untick it later to share the task (the modal says that everyone then sees and changes it). **A shared task can't be made private**: its box is disabled, and the API and `update_task` answer 400 "A shared task stays shared". **Where a task is kept is the one thing that decides who sees it; its tags never do.** A new task starts private where that is what you'd expect: from an embed on a page in your private folder, from `/tasks?list=` of a list declared there, from the editor's Make task on a private page, from New task / `c t` when your default list is in your private folder. Cards of private tasks show 🔒 (`.task-private`). Everything else (shared tasks) is everyone's to see and change, as shared pages are.

- **Storage**: shared tasks stay in `_tasks/tasks.json`, `completed.json`, `completed-YYYY.json`; a user's private ones are in the same three kinds of file in `private/<user>/_tasks/` (`tasksDir(owner)`), created on their first private task. A task's file says whose it is: the task's `Owner` (`go/task.go`) is not written into it, it is set from the folder a task was read from (`eachOwner`), and the API shows it as `"private": true|false` (only with users: without them the API's JSON is as before). Toggling Private (`private` in `POST`/`PUT /api/tasks`, `batch-update`) moves the task between the files in one commit. Ids are random UUIDs, unique across all files; restoring a deleted task (undo) never takes an id another file has (`taskIDsLocked`) and keeps it private.
- **Reading and writing** (`go/taskstore.go`): every reader takes the user and reads the shared files and theirs (`taskOwners(user)`: `readTasks`, `readCompleted`, `readAll`, `allTasks`, `readForWriteLocked`, `findTasks`, `resolveTaskRefs`, `findTaskBacklinks`, `completedInYear`, `completedYears`); Zone itself (`""`) reads only the shared ones. A write splits the tasks by owner (`byOwner`) and writes the files that changed, all in one commit; a task can only be written by its own user, since another user's is never read for them. One lock (`tasksMu`) for all files, taken by reads across them too (`openTasks` for `GET /api/tasks`, `readAll`, `allTasks`): a task made private or shared moves between two files, and a read between their writes would miss it. What Zone does over every task list covers every user's files (`everyOwner`): the yearly archive at start (`archiveOldCompleted`), a rename's links in tasks (`renamePageRefs`), the search index (`everyTask`, filtered per user by `canSeeTask`, `hiddenDoc`). A series' next occurrence stays private (`spawnRecurring`). A private task's pasted files are private too (the notes' editor sends `private/<you>/…` as the upload's page).
- **Another user's private task is no task**: by id the routes answer 404 as for an id no task has (`DELETE /api/tasks/<id>` of an unknown id stays a 204, as before); lists, counts, Completed and its years, the due count, Linked tasks and the section chips leave it out; a `[[task:…]]` to it renders as for a deleted task. A shared page that refers to a private task doesn't carry its title into the search index (`taskRefsAsTitles` resolves a page's references as its owner, or for a shared page as no one).
- **Lists and pins are per user**: a list declared on a page in your private folder (`[[tasks: list=…]]`) exists only for you (`taskLists(user)`); for others its name is a plain tag. When you and a shared page both declare one, yours is its home for you (`taskLists`: your own declaration first, A–Z, else the first shared one A–Z), whatever the pages' names; for the others the shared page is. Likewise a `pin=1` embed in your private folder pins its list for you alone, ahead of shared pins (`lookupPinnedIn(…, user)`), so with no `pin=default` your own list is the default one, and the Tasks link, its counts and New task's tags are your own. Pins on shared pages are everyone's: a list pinned there is pinned for every user. **So one list name can start tasks in different places for different users**: when alice declares `gifts` in her folder and a shared page declares it too, a new task in `/tasks?list=gifts` starts private for her and shared for bob. The tasks she tags `#gifts` that are shared show in the list for everyone, her private ones only for her.
- **Sharing a task**: unticking Private (`private: false` in `PUT /api/tasks`, `batch-update`, `update_task`) moves your task from your files to the shared ones, in one commit; it is an event in the task's History (`shared`, by who did it; older tasks may show `private` events from when tasks could move the other way). `private: true` on a task that is shared answers 400; it is accepted only when a task is created. The tasks' undo of an edit doesn't restore the Private box, so it never tries to take a shared task back.
- **Private lists are a location, not a tag**: a list declared on a page in your private folder is yours alone (Lists and pins are per user, above), and a new task made from `/tasks?list=` of that list, or from an embed on that page, starts private. A tag never moves a task: adding `#gifts` to a task, in the modal, a batch or `update_task`, leaves it where it is; creating one with the tag shared, shared. The tag of your private list on a shared task shows to others as a plain tag.
- **History**: `private/<user>/_tasks/` files show only to that user in history views (`canSeePath`); the commit messages ("Update task") name no task.

## Who made a change

- **Commits**: every commit Zone makes for a user's action names them as its author, `alice <alice@zone>` (`gitCommit(user, …)`); the committer stays Zone. Commits run one at a time (`commitMu` around `git add` and `git commit`), and each commits only its own paths, so one user's files never go into another's commit. Commits Zone makes on its own (start-up, archiving the tasks) are Zone's: the wiki's git committer is `Zone <zone@localhost>` (`setCommitter`, also taking over from `Leaf <leaf@localhost>`, the one from before Leaf was called Zone), and the history shows no name for its commits, nor for the old ones by Leaf (`commitAuthor`). **A draft is committed in its author's name**: Zone remembers who auto-saved a page's uncommitted text (`drafts` in `go/merge.go`, in memory: the editor's auto-save and a ticked checkbox note it, a commit of the file forgets it). Before another user's save, Done or checkbox tick on that page (and before a write that changes other pages on the way: a rename re-pointing links, a folder move, Append to page, `commitOthersDrafts`), the draft is committed first as its author's `Save <slug>` (`commitOthersDraft`), so it is in git under their name, not in the other's commit; one person's own auto-saves stay uncommitted. A write that replaces or removes the page's text (a delete, rename or restore, Keep mine, Reload theirs, and every assistant's write) commits whatever the page holds uncommitted first, the writer's own draft too, so it is never lost and the write's own commit holds only its change (`keepPending`, `keepPendingPages` in `go/pageops.go`: one commit per author); Commit file and Commit all commit a draft as its author too (`commitAuthorOf`). Text whose author Zone doesn't know (edited on disk, or auto-saved before a restart) is committed as before: by the one committing, or by Zone for an assistant's write. **In another user's private folder the folder says whose it is**: a rename, folder move or Append that rewrites links first commits every uncommitted file there in its owner's name, one commit per owner (`Save private/alice/diary`, or `Save 5 files in private/alice`; `commitOthersDrafts`), so a rename of a shared page never carries their unfinished text in its commit. Without users all commits are Zone's, as before.
- **History**: a page's history shows the author after a version's label ("Edited · alice", `.hist-by`; `GitEntry.Author`, `commitAuthor`), and the MCP `history` tool adds "(by alice)" to a version's or a change's message. Zone's own commits, and every commit in a wiki without users, show no name.
- **Tasks**: comments and History events record who wrote or did them (`by`, see Comments and History in `docs/spec/tasks.md`): the cards and the edit modal show "12 Mar 09:30 · alice" (`commentStamp` in `tasks.js`), MCP's task text names a comment's author "(alice)". Editing a comment keeps its author. Any user may edit or delete any comment on a task they can see, as they may change the task itself.
